## What is a SELF JOIN?

A SELF JOIN joins a table with itself. The table appears twice in the query under different aliases - it's just a regular JOIN where both sides reference the same table.

**When do you need it?**
- Hierarchical data (employee-manager, category-parent)
- Comparing rows within the same table
- Finding pairs or relationships within one dataset

## Employee-Manager Hierarchy

The classic use case - an `employees` table where each employee has a `manager_id` pointing to another employee in the same table:

```
employees:
id | name     | manager_id
1  | CEO      | NULL
2  | Alice    | 1
3  | Bob      | 1
4  | Charlie  | 2
5  | Diana    | 2
```

```sql
-- Each employee with their manager's name
SELECT
  e.name  AS employee,
  m.name  AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;

-- Result:
-- CEO      | NULL    (no manager)
-- Alice    | CEO
-- Bob      | CEO
-- Charlie  | Alice
-- Diana    | Alice
```

We use `LEFT JOIN` (not INNER) so the CEO (whose `manager_id` is NULL) still appears.

## Three Levels Deep

```sql
-- Employee, their manager, and their manager's manager
SELECT
  e.name   AS employee,
  m.name   AS manager,
  gm.name  AS grand_manager
FROM employees e
LEFT JOIN employees m  ON e.manager_id  = m.id
LEFT JOIN employees gm ON m.manager_id  = gm.id;
```

## Finding Pairs Within the Same Table

```sql
-- Find all pairs of products in the same category
SELECT
  a.name AS product_1,
  b.name AS product_2,
  a.category_id
FROM products a
JOIN products b
  ON  a.category_id = b.category_id
  AND a.id < b.id      -- prevents (A,B) and (B,A) duplicates and (A,A) self-pairs
ORDER BY a.category_id;
```

The `a.id < b.id` condition is crucial - without it you'd get every pair twice plus each product paired with itself.

## Comparing Rows - Orders Placed on the Same Day

```sql
-- Find pairs of orders by the same customer on the same day
SELECT
  a.id      AS order_1,
  b.id      AS order_2,
  a.customer_id,
  DATE(a.created_at) AS order_date
FROM orders a
JOIN orders b
  ON  a.customer_id = b.customer_id
  AND DATE(a.created_at) = DATE(b.created_at)
  AND a.id < b.id;
```

## Finding Consecutive Events

```sql
-- Find users who placed orders on consecutive days
WITH daily_orders AS (
  SELECT DISTINCT customer_id, DATE(created_at) AS order_date
  FROM orders
)
SELECT DISTINCT a.customer_id
FROM daily_orders a
JOIN daily_orders b
  ON  a.customer_id = b.customer_id
  AND b.order_date  = a.order_date + INTERVAL '1 day';
```

## Interview Question: How do you query a hierarchical table?

**Answer:** Use a SELF JOIN for shallow hierarchies (2-3 levels) or a recursive CTE for unlimited depth.

```sql
-- Shallow (2 levels): SELF JOIN
SELECT e.name AS employee, m.name AS manager
FROM employees e LEFT JOIN employees m ON e.manager_id = m.id;

-- Deep (unlimited levels): Recursive CTE
WITH RECURSIVE org AS (
  SELECT id, name, manager_id, 0 AS level
  FROM employees WHERE manager_id IS NULL  -- root

  UNION ALL

  SELECT e.id, e.name, e.manager_id, o.level + 1
  FROM employees e
  JOIN org o ON e.manager_id = o.id        -- recursive step
)
SELECT * FROM org ORDER BY level, name;
```

## Summary

- A SELF JOIN joins a table to itself using two different aliases
- Required for hierarchical data (employee-manager, category tree)
- Use `a.id < b.id` when finding pairs to avoid duplicates
- Use LEFT JOIN when some rows have no parent (root of hierarchy)
- For unlimited-depth hierarchies, use a recursive CTE instead

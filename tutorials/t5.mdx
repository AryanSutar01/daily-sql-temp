## The SELECT Statement

`SELECT` is the most-used SQL command. It retrieves data from one or more tables. Every data query starts with SELECT.

### Basic Syntax

```sql
SELECT column1, column2, ...
FROM table_name;
```

### Select All Columns

```sql
-- * returns every column in the table
SELECT * FROM users;
```

> `SELECT *` is convenient for exploration but avoid it in production code - it fetches unnecessary columns, breaks when columns are added/removed, and prevents index-only scans.

### Select Specific Columns

```sql
-- Only retrieve what you need
SELECT name, email FROM users;

SELECT id, name, price FROM products;
```

### Selecting Expressions

You can calculate values directly in SELECT:

```sql
-- Arithmetic
SELECT name, price, price * 1.18 AS price_with_gst FROM products;

-- String concatenation
SELECT first_name || ' ' || last_name AS full_name FROM users;

-- Conditional
SELECT name, CASE WHEN stock > 0 THEN 'In Stock' ELSE 'Out of Stock' END AS availability
FROM products;
```

## Column Aliases - AS

`AS` gives a column (or expression) a readable name in the output.

```sql
-- Rename a column in the result
SELECT name AS customer_name, email AS contact FROM users;

-- Alias an expression
SELECT salary * 12 AS annual_salary FROM employees;

-- Alias a table (shorthand)
SELECT u.name, u.email FROM users AS u;
SELECT u.name, u.email FROM users u;  -- AS is optional
```

**Important:** Column aliases defined in SELECT cannot be used in WHERE (WHERE runs before SELECT).

```sql
-- ❌ Error: annual_salary alias not available in WHERE
SELECT salary * 12 AS annual_salary FROM employees
WHERE annual_salary > 600000;

-- ✅ Repeat the expression
WHERE salary * 12 > 600000;

-- ✅ Or wrap in a subquery
SELECT * FROM (
  SELECT *, salary * 12 AS annual_salary FROM employees
) t
WHERE annual_salary > 600000;
```

## DISTINCT - Remove Duplicates

```sql
-- Get unique cities where users live
SELECT DISTINCT city FROM users;

-- Get unique (city, status) combinations
SELECT DISTINCT city, status FROM users;

-- Count unique values
SELECT COUNT(DISTINCT city) AS unique_cities FROM users;
```

## FROM - The Source Table

`FROM` specifies which table(s) to query. It can also reference:

### Subquery as a Table

```sql
SELECT *
FROM (
  SELECT customer_id, SUM(total) AS total_spent
  FROM orders
  GROUP BY customer_id
) AS customer_summary
WHERE total_spent > 10000;
```

### Multiple Tables (Implicit Join - Old Style)

```sql
-- Old-style join (avoid this - use explicit JOIN instead)
SELECT u.name, o.total
FROM users u, orders o
WHERE u.id = o.customer_id;

-- Modern explicit syntax (much clearer)
SELECT u.name, o.total
FROM users u
JOIN orders o ON u.id = o.customer_id;
```

## SELECT with Literal Values

```sql
-- Include constants in output
SELECT
  name,
  'active'       AS status,
  0              AS default_score,
  NOW()          AS exported_at
FROM users;
```

## SELECT without FROM

Some databases allow SELECT without a table:

```sql
-- PostgreSQL / MySQL
SELECT 1 + 1;          -- 2
SELECT NOW();           -- current timestamp
SELECT UPPER('hello'); -- 'HELLO'
SELECT 'test';         -- 'test'

-- Used in EXISTS checks
WHERE EXISTS (SELECT 1 FROM orders WHERE customer_id = u.id)
-- SELECT 1 is a common pattern - returns a constant, fast
```

## Controlling Output - Column Order

Columns appear in SELECT output in the order you list them:

```sql
-- This determines column order in results
SELECT id, name, email, created_at FROM users;

-- Different order
SELECT created_at, email, name, id FROM users;
```

## SELECT with LIMIT (Preview Data)

```sql
-- Quick look at a table's structure and sample data
SELECT * FROM orders LIMIT 5;

-- Without LIMIT on a large table → millions of rows returned → very slow
```

## Putting It Together

```sql
-- A complete foundational query
SELECT
  u.id,
  u.name                    AS customer,
  u.email,
  u.city,
  u.created_at::DATE        AS joined_date
FROM users u
WHERE u.status = 'active'
  AND u.city IN ('Mumbai', 'Delhi', 'Bangalore')
ORDER BY u.created_at DESC
LIMIT 50;
```

## Interview Question: What's the difference between SELECT * and SELECT column?

**Answer:**
- `SELECT *` retrieves every column - convenient but wasteful. It fetches more data over the network, prevents the query planner from using index-only scans, and breaks if columns are reordered or removed.
- `SELECT column1, column2` retrieves only what you need - faster, more explicit, safer to maintain.
- In interviews, always select specific columns to show you understand query efficiency.

## Summary

- `SELECT col FROM table` is the foundation of every read query
- Use column aliases (`AS`) to make output readable
- `DISTINCT` removes duplicate rows from results
- `SELECT *` is for exploration only - always name columns in production code
- Column aliases in SELECT cannot be referenced in WHERE (use a subquery or repeat the expression)
- Include `LIMIT` when exploring unknown tables to avoid pulling millions of rows

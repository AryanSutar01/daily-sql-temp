## What is NULL?

NULL means **unknown**, **missing**, or **not applicable**. It is not:
- Zero (`0`)
- An empty string (`''`)
- False (`FALSE`)

NULL is the absence of any value. A user's `phone` column being NULL means we don't know their phone number - not that their phone number is zero or empty.

```sql
-- These are all different:
phone = NULL   -- unknown
phone = ''     -- known to be empty string
phone = '0'    -- known to be the string '0'
phone = 0      -- type error (phone is VARCHAR)
```

## Three-Valued Logic

SQL uses **three-valued logic**: TRUE, FALSE, and UNKNOWN.

Any comparison with NULL returns UNKNOWN (not TRUE, not FALSE):

```sql
NULL = NULL    → UNKNOWN (not TRUE!)
NULL != NULL   → UNKNOWN
NULL > 5       → UNKNOWN
NULL = 'hello' → UNKNOWN
1 = NULL       → UNKNOWN
```

This is why `WHERE phone = NULL` never returns any rows - it evaluates to UNKNOWN for every row, and WHERE only keeps TRUE.

```sql
-- ❌ Never returns rows
SELECT * FROM users WHERE phone = NULL;

-- ✅ Correct
SELECT * FROM users WHERE phone IS NULL;
SELECT * FROM users WHERE phone IS NOT NULL;
```

## NULL in WHERE Conditions

```sql
-- Find users without a phone number
SELECT name, email FROM users WHERE phone IS NULL;

-- Find users who have a phone number
SELECT name, email FROM users WHERE phone IS NOT NULL;

-- ❌ Common mistake: this finds NOTHING
SELECT * FROM users WHERE phone != '9999999999';
-- Rows where phone IS NULL are excluded! NULL != anything = UNKNOWN

-- ✅ To include NULLs:
SELECT * FROM users
WHERE phone != '9999999999' OR phone IS NULL;
```

## NULL in JOINs

NULL foreign keys never match any row in a JOIN:

```sql
-- If order.sales_rep_id is NULL, this order will not appear in INNER JOIN
SELECT o.id, u.name AS sales_rep
FROM orders o
JOIN users u ON o.sales_rep_id = u.id;
-- Orders with NULL sales_rep_id are excluded

-- Use LEFT JOIN to include them
SELECT o.id, COALESCE(u.name, 'Unassigned') AS sales_rep
FROM orders o
LEFT JOIN users u ON o.sales_rep_id = u.id;
```

## NULL in Aggregations

Most aggregate functions ignore NULLs:

```sql
-- If 3 out of 5 salaries are NULL:
SELECT COUNT(*)      FROM employees;  -- 5 (counts all rows)
SELECT COUNT(salary) FROM employees;  -- 2 (counts non-NULL only)
SELECT SUM(salary)   FROM employees;  -- sum of 2 non-NULL values
SELECT AVG(salary)   FROM employees;  -- average of 2 non-NULL values (not 5!)
SELECT MIN(salary)   FROM employees;  -- min of 2 non-NULL values
```

**Interview trap:** AVG ignores NULLs - it divides by the count of non-NULL values, not total rows. This can give a misleadingly high average if many values are NULL.

```sql
-- These give different results when salary has NULLs:
SELECT AVG(salary) FROM employees;
-- = SUM(salary) / COUNT(salary)  ← only non-NULL rows

SELECT SUM(salary) / COUNT(*) FROM employees;
-- = SUM(salary) / total_rows  ← includes NULL rows in denominator
-- This gives a lower (more conservative) average
```

## NULL in NOT IN - The Most Dangerous Trap

```sql
-- Find users who haven't placed any order
SELECT * FROM users
WHERE id NOT IN (SELECT customer_id FROM orders);

-- ⚠️ If ANY customer_id in orders is NULL → returns ZERO rows!
-- Why? NOT IN with NULL:
-- id NOT IN (1, 2, NULL)
-- = id != 1 AND id != 2 AND id != NULL
-- = id != 1 AND id != 2 AND UNKNOWN
-- = UNKNOWN → row excluded
```

**Always use NOT EXISTS for this pattern:**

```sql
-- ✅ Handles NULLs correctly
SELECT * FROM users u
WHERE NOT EXISTS (
  SELECT 1 FROM orders o WHERE o.customer_id = u.id
);
```

## COALESCE - Replace NULL with a Default

`COALESCE` returns the first non-NULL value from a list of arguments:

```sql
COALESCE(value1, value2, value3, ...)
-- Returns the first argument that is not NULL

-- Replace NULL phone with 'Not provided'
SELECT name, COALESCE(phone, 'Not provided') AS phone FROM users;

-- Try multiple fallbacks
SELECT name, COALESCE(phone, mobile, email, 'No contact') AS contact
FROM users;

-- Replace NULL in calculations
SELECT name, price - COALESCE(discount, 0) AS final_price FROM products;
-- Without COALESCE: price - NULL = NULL ← wrong!
-- With COALESCE: price - 0 = price ← correct for no discount

-- In aggregations
SELECT SUM(COALESCE(tip_amount, 0)) FROM orders;
```

## NULLIF - Convert a Value to NULL

`NULLIF(a, b)` returns NULL if a equals b, otherwise returns a. Primarily used to avoid divide-by-zero errors:

```sql
-- ❌ Division by zero error
SELECT total_revenue / total_orders FROM stats;

-- ✅ Returns NULL when total_orders = 0 (no error)
SELECT total_revenue / NULLIF(total_orders, 0) AS avg_order_value FROM stats;

-- Convert 'N/A' strings to NULL
SELECT NULLIF(country, 'N/A') AS country FROM contacts;

-- Empty string to NULL
SELECT NULLIF(phone, '') AS phone FROM users;
```

## IS DISTINCT FROM / IS NOT DISTINCT FROM

These operators treat NULL as equal to NULL - useful when you need to compare values that might be NULL:

```sql
-- Standard comparison: NULL = NULL → UNKNOWN
WHERE old_status = new_status  -- NULL columns never match

-- IS NOT DISTINCT FROM: NULL = NULL → TRUE
WHERE old_status IS NOT DISTINCT FROM new_status

-- Practical: find rows where a value actually changed
WHERE old_value IS DISTINCT FROM new_value
-- = "they are different, even if one or both are NULL"
```

## Practical NULL Handling Patterns

```sql
-- Clean display: replace all NULLs with readable defaults
SELECT
  name,
  COALESCE(phone,  'No phone')    AS phone,
  COALESCE(city,   'Unknown')     AS city,
  COALESCE(bio,    'No bio yet')  AS bio,
  COALESCE(last_login::TEXT, 'Never') AS last_login
FROM users;

-- Safe percentage calculation
SELECT
  category,
  COUNT(*) AS total,
  COUNT(CASE WHEN status = 'active' THEN 1 END) AS active,
  ROUND(
    COUNT(CASE WHEN status = 'active' THEN 1 END) * 100.0
    / NULLIF(COUNT(*), 0),
    2
  ) AS active_pct
FROM users
GROUP BY category;
```

## Summary

- NULL means unknown/missing - not zero, not empty string
- Any comparison with NULL returns UNKNOWN, not TRUE or FALSE
- Always use `IS NULL` and `IS NOT NULL` - never `= NULL`
- `NOT IN` with a nullable subquery returns zero rows - use `NOT EXISTS` instead
- `AVG` ignores NULLs - this can skew results if many values are NULL
- `COALESCE` returns the first non-NULL value - essential for replacing NULLs with defaults
- `NULLIF` converts a specific value to NULL - prevents divide-by-zero errors
- NULL foreign keys never match in JOINs - use LEFT JOIN to include them

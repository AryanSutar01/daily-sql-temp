## What is SQL?

SQL - pronounced "S-Q-L" or "sequel" - stands for **Structured Query Language**. It is the standard language used to communicate with relational databases. With SQL you can:

- **Create** tables and databases
- **Insert** new data
- **Query** (read) data
- **Update** existing data
- **Delete** data
- **Control** who has access to what

SQL was developed at IBM in the early 1970s, became an ANSI standard in 1986, and today powers nearly every application that stores structured data - from banking systems to e-commerce platforms to analytics dashboards.

## What is a Database?

A **database** is an organized collection of structured data stored electronically. Think of it as a digital filing cabinet where everything is indexed and retrievable.

```
Without a database:                With a database:
- Files scattered everywhere       - Centralized storage
- No easy search                   - Query in milliseconds
- No relationships                 - Relationships between data
- No concurrent access             - Multiple users simultaneously
- Data duplication everywhere      - Data stored once, referenced everywhere
```

## What is a RDBMS?

A **Relational Database Management System (RDBMS)** is the software that:
1. Stores your data in structured tables
2. Manages how that data is accessed and modified
3. Enforces rules (constraints) on the data
4. Handles multiple users accessing data simultaneously
5. Ensures data is not lost or corrupted

## The Relational Model

"Relational" means data is organized into **tables** that can be **related** to each other through shared values.

### Tables

A table stores data about one type of thing (users, products, orders). It has:
- **Columns** (also called fields or attributes) - define what data is stored
- **Rows** (also called records or tuples) - individual data entries

```
users table:
+----+----------+---------------------+--------+
| id | name     | email               | city   |
+----+----------+---------------------+--------+
| 1  | Alice    | alice@email.com     | Mumbai |
| 2  | Bob      | bob@email.com       | Delhi  |
| 3  | Charlie  | charlie@email.com   | Pune   |
+----+----------+---------------------+--------+
```

### Relationships Between Tables

Tables relate to each other through **keys**:

```
users table          orders table
+---------+          +----+-------------+--------+
| id (PK) |←----+    | id | customer_id | amount |
| name    |     +----| 1  | 1           | 500    |
| email   |          | 2  | 1           | 300    |
+---------+          | 3  | 2           | 750    |
                     +----+-------------+--------+
                              ↑
                         Foreign Key → references users.id
```

## Key Concepts

### Primary Key (PK)
A column (or combination of columns) that **uniquely identifies each row**. No two rows can have the same primary key. Cannot be NULL.

```sql
CREATE TABLE users (
  id    INT PRIMARY KEY,    -- unique, not null
  name  VARCHAR(100),
  email VARCHAR(255)
);
```

### Foreign Key (FK)
A column that **references the primary key of another table**. Creates the "relationship" in relational database.

```sql
CREATE TABLE orders (
  id          INT PRIMARY KEY,
  customer_id INT REFERENCES users(id),  -- FK → users.id
  amount      DECIMAL(10,2)
);
```

### Schema
The **structure** of a database - all its tables, columns, data types, and relationships. It's like the blueprint of the database.

## How SQL Works with RDBMS

When you write a SQL query, here's what happens:

```
1. You write SQL:
   SELECT name FROM users WHERE city = 'Mumbai';

2. SQL Parser checks syntax

3. Query Planner figures out the most efficient way to fetch the data

4. Query Executor accesses the data files on disk

5. Results returned to you
       ↓
   +----------+
   | name     |
   +----------+
   | Alice    |
   +----------+
```

## SQL vs NoSQL

A common interview question: *"When would you use SQL vs NoSQL?"*

| Feature | SQL (Relational) | NoSQL |
|---------|-----------------|-------|
| Data structure | Tables (rows & columns) | Documents, Key-Value, Graph |
| Schema | Fixed, defined upfront | Flexible, dynamic |
| Relationships | Strong, enforced by FKs | Application handles relationships |
| Consistency | ACID compliant | Often eventual consistency |
| Query language | Standardized SQL | Varies (MongoDB query, Redis commands) |
| Best for | Structured data, complex queries, transactions | Unstructured data, massive scale, rapid iteration |
| Examples | PostgreSQL, MySQL, SQLite | MongoDB, Redis, DynamoDB, Cassandra |

**Use SQL when:** data is structured, relationships matter, consistency is critical (banking, e-commerce, user accounts)

**Use NoSQL when:** schema changes frequently, data is unstructured (logs, social media), you need massive horizontal scale

## Summary

- SQL is the standard language for interacting with relational databases
- An RDBMS stores data in tables with rows and columns
- Tables relate to each other through primary and foreign keys
- The most popular RDBMS are PostgreSQL, MySQL, and SQLite
- SQL is used everywhere - from small apps to systems handling billions of rows

## The WHERE Clause

`WHERE` filters rows before they are returned. Only rows where the condition evaluates to TRUE are included in the result.

```sql
SELECT * FROM users WHERE city = 'Mumbai';
SELECT * FROM products WHERE price < 1000;
SELECT * FROM orders WHERE status = 'pending';
```

## Comparison Operators

| Operator | Meaning | Example |
|----------|---------|---------|
| `=` | Equal to | `city = 'Mumbai'` |
| `!=` or `<>` | Not equal to | `status != 'inactive'` |
| `>` | Greater than | `price > 1000` |
| `<` | Less than | `age < 18` |
| `>=` | Greater than or equal | `salary >= 50000` |
| `<=` | Less than or equal | `discount <= 10` |

```sql
SELECT * FROM products WHERE price >= 500 AND price <= 2000;
SELECT * FROM users WHERE age != 0;
SELECT * FROM orders WHERE created_at > '2024-01-01';
```

## Logical Operators: AND, OR, NOT

### AND - All conditions must be true

```sql
SELECT * FROM users
WHERE city = 'Mumbai' AND status = 'active';

SELECT * FROM products
WHERE price < 5000 AND stock > 0 AND is_active = TRUE;
```

### OR - At least one condition must be true

```sql
SELECT * FROM users
WHERE city = 'Mumbai' OR city = 'Delhi';
```

### NOT - Negates a condition

```sql
SELECT * FROM users WHERE NOT status = 'banned';
-- Same as:
SELECT * FROM users WHERE status != 'banned';
```

### Operator Precedence - Use Parentheses!

AND has higher precedence than OR. Always use parentheses when mixing them:

```sql
-- ❌ Ambiguous - reads as: city='Mumbai' OR (city='Delhi' AND status='active')
WHERE city = 'Mumbai' OR city = 'Delhi' AND status = 'active';

-- ✅ Clear intent with parentheses
WHERE (city = 'Mumbai' OR city = 'Delhi') AND status = 'active';
```

## BETWEEN

Checks if a value falls within an inclusive range:

```sql
-- age >= 20 AND age <= 30
SELECT * FROM users WHERE age BETWEEN 20 AND 30;

-- Date range
SELECT * FROM orders
WHERE created_at BETWEEN '2024-01-01' AND '2024-12-31';

-- NOT BETWEEN
SELECT * FROM products WHERE price NOT BETWEEN 100 AND 500;
```

> **BETWEEN is inclusive** - both endpoints are included.

## IN - Match Any Value in a List

Cleaner than multiple OR conditions:

```sql
-- Instead of:
WHERE city = 'Mumbai' OR city = 'Delhi' OR city = 'Pune'

-- Use:
WHERE city IN ('Mumbai', 'Delhi', 'Pune')

-- NOT IN
WHERE city NOT IN ('Mumbai', 'Delhi')

-- IN with subquery
WHERE id IN (SELECT DISTINCT customer_id FROM orders WHERE total > 5000)
```

**⚠️ NOT IN with NULL - a common interview trap:**

```sql
-- If the subquery returns any NULL, NOT IN returns ZERO rows
WHERE id NOT IN (SELECT customer_id FROM orders)
-- If customer_id has one NULL → returns nothing!

-- ✅ Use NOT EXISTS instead (handles NULLs correctly)
WHERE NOT EXISTS (SELECT 1 FROM orders WHERE orders.customer_id = users.id)
```

## LIKE - Pattern Matching

### Wildcards

| Wildcard | Matches |
|----------|---------|
| `%` | Zero or more characters |
| `_` | Exactly one character |

```sql
-- Starts with 'A'
SELECT * FROM users WHERE name LIKE 'A%';

-- Ends with 'Kumar'
SELECT * FROM users WHERE name LIKE '%Kumar';

-- Contains 'raj' anywhere
SELECT * FROM users WHERE name LIKE '%raj%';

-- Second character is 'a' (exactly 4 chars)
SELECT * FROM users WHERE name LIKE '_a__';

-- Starts with 'PRD' followed by exactly 3 chars
SELECT * FROM products WHERE sku LIKE 'PRD___';
```

### Case Sensitivity

```sql
-- MySQL: LIKE is case-insensitive by default

-- PostgreSQL: LIKE is case-sensitive; use ILIKE for case-insensitive
SELECT * FROM users WHERE name ILIKE 'alice%';  -- matches 'Alice', 'ALICE', 'alice'

-- NOT LIKE
SELECT * FROM users WHERE email NOT LIKE '%@gmail.com';
```

## IS NULL / IS NOT NULL

NULL means "unknown" or "missing." You cannot compare NULL with `=` - it always returns UNKNOWN.

```sql
-- ❌ Wrong: always returns no rows
SELECT * FROM users WHERE phone = NULL;

-- ✅ Correct
SELECT * FROM users WHERE phone IS NULL;      -- has no phone
SELECT * FROM users WHERE phone IS NOT NULL;  -- has a phone
```

```sql
-- Find orders with no assigned sales rep
SELECT * FROM orders WHERE sales_rep_id IS NULL;

-- Find users who haven't logged in yet
SELECT * FROM users WHERE last_login IS NULL;
```

## Combining Everything - Real Example

```sql
-- Find active premium users from metro cities
-- aged 25-45, with a verified email, who joined in 2024
SELECT
  id, name, email, city, age
FROM users
WHERE
  status = 'active'
  AND tier = 'premium'
  AND city IN ('Mumbai', 'Delhi', 'Bangalore', 'Pune', 'Chennai')
  AND age BETWEEN 25 AND 45
  AND email IS NOT NULL
  AND email LIKE '%@%'
  AND created_at >= '2024-01-01'
  AND created_at < '2025-01-01'
ORDER BY created_at DESC;
```

## Interview Questions

**Q: What is the difference between WHERE and HAVING?**

- `WHERE` filters individual rows **before** grouping
- `HAVING` filters groups **after** `GROUP BY`
- `WHERE` cannot use aggregate functions; `HAVING` can

```sql
SELECT department, AVG(salary) AS avg_sal
FROM employees
WHERE status = 'active'      -- filters rows first
GROUP BY department
HAVING AVG(salary) > 60000;  -- filters groups after
```

**Q: Why does `NOT IN (subquery)` sometimes return no rows?**

If the subquery returns any NULL value, `NOT IN` returns no rows because `x NOT IN (..., NULL)` evaluates to UNKNOWN (not FALSE) for every x. Solution: use `NOT EXISTS` instead.

## Summary

- `WHERE` filters rows before they are returned
- AND requires all conditions to be true; OR requires at least one
- Always use parentheses when mixing AND and OR
- `BETWEEN` is inclusive on both ends
- `IN` is cleaner than multiple ORs; beware `NOT IN` with nullable columns
- `LIKE` uses `%` (any chars) and `_` (one char) for pattern matching
- Never use `= NULL` - always use `IS NULL` or `IS NOT NULL`

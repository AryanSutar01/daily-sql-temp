## What Is Serialization and Why Does It Matter?

Programs hold state in memory — Python objects, data structures, machine learning model weights. When your program exits, all that memory is freed. Serialization solves the **persistence and transport problem**: it converts a Python object into a format that can be:
- Stored to disk and reloaded later (state persistence)
- Sent over a network to another process or service (data exchange)
- Shared between different programming languages (interoperability)

The serialization format you choose determines three properties:
1. **What types can be serialized** — Python-only vs universally understood
2. **Whether it's human-readable** — binary blob vs text
3. **Safety** — whether it can execute code on deserialization

```
Format      Module      Binary?  Python-only?  Human-readable?  Safe?
------      ------      -------  ------------  ---------------  -----
pickle      pickle      Yes      Yes           No               No (unsafe!)
JSON        json        No       No            Yes              Yes
YAML        pyyaml      No       No            Yes              Mostly*
MessagePack msgpack     Yes      No            No               Yes
Protocol    protobuf    Yes      No            No               Yes
```

## pickle — Python-Native Serialization

`pickle` can serialize almost any Python object — custom class instances, functions, closures, NumPy arrays, scikit-learn models, entire class hierarchies. It does this by storing enough information to reconstruct the object, including the class definition's location and the object's internal state.

```python
import pickle

# Serialize to bytes
data = {"name": "Alice", "scores": [95, 88, 92], "active": True}
serialized = pickle.dumps(data)   # bytes object
print(type(serialized))   # <class 'bytes'>
print(serialized[:20])    # b'\x80\x05\x95...' — binary format

# Deserialize from bytes
restored = pickle.loads(serialized)
print(restored)   # {'name': 'Alice', 'scores': [95, 88, 92], 'active': True}
print(data == restored)   # True
```

### Save and Load Files

```python
import pickle

# Save to file
model = {"weights": [0.1, 0.5, 0.3], "bias": 0.01, "accuracy": 0.95}

with open("model.pkl", "wb") as f:   # write binary mode — mandatory for pickle
    pickle.dump(model, f)

# Load from file
with open("model.pkl", "rb") as f:   # read binary mode
    loaded = pickle.load(f)

print(loaded["accuracy"])   # 0.95
```

### Pickling Custom Objects

When pickle serializes a class instance, it stores the module path and class name plus the instance's `__dict__`. When unpickling, it imports the class from that path and reconstructs the instance. This means the class definition must be importable at unpickling time.

```python
import pickle

class User:
    def __init__(self, name, age, email):
        self.name = name
        self.age = age
        self.email = email

    def greet(self):
        return f"Hi, I'm {self.name}"

user = User("Alice", 30, "alice@example.com")

# Pickle and restore
data = pickle.dumps(user)
restored = pickle.loads(data)

print(restored.name)      # Alice
print(restored.greet())   # Hi, I'm Alice
```

### Pickling Functions

```python
import pickle

def square(x):
    return x ** 2

# Functions are pickled by reference — only the module path and function name are stored
# The actual code is NOT serialized
data = pickle.dumps(square)
restored_fn = pickle.loads(data)
print(restored_fn(5))   # 25

# Limitation: the function must exist at the same module path when unpickling
# Lambda functions and locally-defined functions typically cannot be pickled
```

### Controlling Pickling with `__getstate__` / `__setstate__`

Many objects contain attributes that cannot be pickled: open file handles, network connections, database cursors, thread locks. The `__getstate__` / `__setstate__` protocol gives you control over exactly what gets serialized.

```python
import pickle

class DatabaseConnection:
    def __init__(self, host, port):
        self.host = host
        self.port = port
        self.connection = self._connect()   # active connection — cannot be pickled

    def _connect(self):
        return f"<connection to {self.host}:{self.port}>"

    def __getstate__(self):
        """Return only what should be pickled — exclude unpicklable attributes."""
        state = self.__dict__.copy()
        del state["connection"]   # exclude the live connection object
        return state

    def __setstate__(self, state):
        """Restore state after unpickling — reinitialize excluded attributes."""
        self.__dict__.update(state)
        self.connection = self._connect()   # reconnect after deserialization

db = DatabaseConnection("localhost", 5432)
restored = pickle.loads(pickle.dumps(db))
print(restored.host)        # localhost
print(restored.connection)  # <connection to localhost:5432> — reconnected automatically
```

`__getstate__` + `__setstate__` is the correct pattern for any class that holds resources that have a lifecycle — connections, file handles, locks. The class is responsible for "closing" those resources on serialization and "reopening" them on deserialization.

## The pickle Security Vulnerability

This is critical to understand. `pickle` is fundamentally unsafe to use with untrusted data. When Python unpickles an object, it can call arbitrary Python code — including code that deletes files, opens network connections, or executes shell commands.

```python
# DEMONSTRATION ONLY — NEVER RUN UNTRUSTED PICKLES
import pickle
import os

class Exploit:
    def __reduce__(self):
        # __reduce__ controls how an object is reconstructed on unpickling
        # This returns a callable and its arguments — called during loads()
        return (os.system, ("echo 'This could be rm -rf /'",))

malicious = pickle.dumps(Exploit())
# pickle.loads(malicious)  — would execute os.system() — DO NOT RUN
```

**The attack vector**: an attacker who can control a file you load with `pickle.load()` or data you feed to `pickle.loads()` can execute arbitrary code on your machine with your user's permissions. This includes reading secrets from environment variables, exfiltrating files, or compromising the entire system.

**The rule**: only unpickle data that you yourself pickled or that comes from a trusted source you fully control. Never unpickle data from user uploads, API responses, network messages, or any external source.

## json — Language-Agnostic, Human-Readable

JSON (JavaScript Object Notation) is the universal data exchange format. It is human-readable, supported by every programming language, and safe — it cannot execute code.

```python
import json

data = {"name": "Alice", "age": 30, "scores": [95, 88], "active": True}

# Serialize to string
json_str = json.dumps(data)
json_pretty = json.dumps(data, indent=2, sort_keys=True)
print(json_pretty)
# {
#   "active": true,
#   "age": 30,
#   "name": "Alice",
#   "scores": [95, 88]
# }

# Deserialize from string
parsed = json.loads(json_str)
print(parsed["name"])   # Alice

# Save to file
with open("data.json", "w", encoding="utf-8") as f:
    json.dump(data, f, indent=2, ensure_ascii=False)
# ensure_ascii=False — allows non-ASCII characters (Hindi, Arabic, Chinese) to be written literally
# instead of being escaped as \uXXXX sequences

# Load from file
with open("data.json", encoding="utf-8") as f:
    loaded = json.load(f)
```

### JSON Limitations

JSON's type system is much narrower than Python's. This is intentional — it ensures every language can read the data. The trade-off is that you must convert any Python-specific types before serializing.

```python
import json, datetime
from decimal import Decimal

data = {"created": datetime.datetime.now(), "price": Decimal("29.99"), "tags": {1, 2, 3}}
json.dumps(data)   # TypeError: Object of type datetime is not JSON serializable

# Fix 1: Custom JSONEncoder class
class CustomEncoder(json.JSONEncoder):
    def default(self, obj):
        if isinstance(obj, (datetime.datetime, datetime.date)):
            return obj.isoformat()          # "2024-03-15T10:30:45.123456"
        if isinstance(obj, Decimal):
            return float(obj)               # Decimal → float
        if isinstance(obj, set):
            return sorted(list(obj))        # set → sorted list (sorted for determinism)
        return super().default(obj)         # raise TypeError for unknown types

json.dumps(data, cls=CustomEncoder)

# Fix 2: Inline default function (simpler for one-off use)
def serialize(obj):
    if isinstance(obj, datetime.datetime):
        return obj.isoformat()
    raise TypeError(f"Type {type(obj)} not serializable")

json.dumps(data, default=serialize)
```

## pickle vs json — When to Use Which

```
pickle                                   json
------                                   ----
Python-specific only                     Language-agnostic
Binary format                            Text format (human-readable, debuggable)
Supports ALL Python types                Limited types: dict, list, str, int, float, bool, None
Fast for complex Python objects          Slower for complex nested structures
UNSAFE with untrusted data              Safe — cannot execute code
Best for: ML models, Python caches,     Best for: REST APIs, config files,
  inter-process Python communication      data exchange between services
```

**Use pickle** when:
- Saving scikit-learn / PyTorch models to disk
- Caching complex Python objects (parsed ASTs, compiled regex, preprocessed data)
- Communicating between Python processes on the same trusted system

**Use JSON** when:
- Building REST APIs
- Writing configuration files
- Storing data that other languages (JavaScript, Java, Go) will read
- Logging structured data
- Storing data you might need to inspect with a text editor

## shelve — Persistent Dictionary

`shelve` provides a persistent dictionary that saves Python objects to disk using `pickle` under the hood. It's a quick way to add key-value persistence without a database.

```python
import shelve

# shelve gives a dict-like interface backed by a file
with shelve.open("my_store") as db:
    db["user:1"] = {"name": "Alice", "age": 30}
    db["user:2"] = {"name": "Bob", "age": 25}
    db["config"] = {"debug": True, "max_retries": 3}

# Data persists between program runs
with shelve.open("my_store") as db:
    print(db["user:1"])   # {'name': 'Alice', 'age': 30}
    for key in db:
        print(key, db[key])
```

`shelve` is suitable for small single-user applications and development caches. For anything production-grade — concurrent access, large datasets, reliability requirements — use a proper database (SQLite via `sqlite3`, Redis, PostgreSQL).

## Interview Questions

**Q: What is pickling in Python?**
Pickling is the serialization of a Python object into a byte stream using the `pickle` module. It can handle almost any Python object — custom classes, functions, NumPy arrays, scikit-learn models. The byte stream can be stored to disk or transmitted over a network and later deserialized back into an identical Python object using `pickle.loads()`. The reverse process is called unpickling.

**Q: What is the security risk with pickle, and how does it work?**
Python's pickle protocol can call arbitrary code during deserialization. When `pickle.loads()` reconstructs an object, it can invoke any callable defined in the serialized stream — including `os.system()`, `subprocess.run()`, or any other dangerous function. An attacker who controls the pickle data can execute arbitrary code on your machine with your user's permissions. Never unpickle data from any untrusted source — use JSON, MessagePack, or Protocol Buffers for external data.

**Q: What is the difference between `pickle` and `json`?**
`pickle` is Python-specific, stores binary data, supports all Python types, and can execute code on deserialization (unsafe). `json` is text-based, language-agnostic, only supports primitive types (dict, list, str, int, float, bool, None), and is safe. Use pickle for Python-internal persistence (ML models, caches between Python services); use JSON for APIs and cross-language data exchange.

**Q: What are `__getstate__` and `__setstate__` and when do you need them?**
`__getstate__` returns the state that should be pickled — use it to exclude unpicklable attributes like database connections, file handles, and thread locks. `__setstate__` restores the object from that state after unpickling — use it to reinitialize those excluded attributes. They give you fine-grained control over the serialization lifecycle, necessary for any class that manages external resources.

**Q: When would you use `shelve`?**
`shelve` provides dict-like persistent storage backed by pickle — useful for simple single-user applications, development scripts, or caching Python objects without setting up a database. Its limitations: single-writer (no concurrent access), no transactions, and inherits pickle's security risks. For production-grade persistence or concurrent access, use a proper database like SQLite, Redis, or PostgreSQL.

## Summary

- **Serialization** — convert Python object → bytes/string for storage or transport; deserialization is the reverse
- `pickle.dumps()` / `pickle.loads()` — serialize/deserialize bytes in memory
- `pickle.dump(obj, f)` / `pickle.load(f)` — serialize/deserialize to/from a file object
- `__getstate__` / `__setstate__` — control what gets pickled; exclude unpicklable resources, reinitialize them after
- **NEVER** unpickle untrusted data — arbitrary code execution risk via `__reduce__`
- **json.dumps/json.dump** → Python to JSON string/file; `json.loads/json.load` → JSON to Python
- JSON supports: dict, list, str, int, float, bool, None — use `cls=CustomEncoder` or `default=func` for others
- `ensure_ascii=False` — allows non-ASCII characters in JSON output without escaping
- **pickle vs json**: pickle for Python internals and ML models; JSON for cross-system and APIs
- **shelve** — persistent dict backed by pickle; simple key-value storage; not for concurrent/production use

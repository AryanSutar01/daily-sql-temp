## What Are Dunder Methods?

Dunder (double underscore) methods - also called magic methods or special methods - let your custom classes hook into Python's built-in behaviour. They're called automatically by Python, not directly by you.

```python
class Point:
    def __init__(self, x, y):   # called on object creation
        self.x = x
        self.y = y

p = Point(3, 4)   # Python calls p.__init__(3, 4) automatically
```

## Object Lifecycle

```python
class MyClass:
    def __init__(self, value):
        """Called when object is created."""
        self.value = value

    def __del__(self):
        """Called when object is about to be garbage collected."""
        print(f"Deleting object with value {self.value}")

    def __new__(cls, *args, **kwargs):
        """Called before __init__ - creates and returns the instance.
        Rarely overridden except for Singleton or immutable types."""
        instance = super().__new__(cls)
        return instance
```

## String Representation

```python
class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price

    def __str__(self):
        """Human-readable - used by print() and str()"""
        return f"{self.name} - ₹{self.price:.2f}"

    def __repr__(self):
        """Developer/debug representation - used in REPL, repr(), logs"""
        return f"Product(name={self.name!r}, price={self.price})"

p = Product("Laptop", 49999)
print(p)        # Laptop - ₹49999.00        (uses __str__)
repr(p)         # Product(name='Laptop', price=49999)  (uses __repr__)
f"{p}"          # uses __str__
f"{p!r}"        # uses __repr__
```

## Comparison Operators

```python
from functools import total_ordering

@total_ordering   # auto-generates missing comparison methods from __eq__ and one of __lt__/__gt__
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    def __eq__(self, other):
        if not isinstance(other, Temperature):
            return NotImplemented
        return self.celsius == other.celsius

    def __lt__(self, other):
        if not isinstance(other, Temperature):
            return NotImplemented
        return self.celsius < other.celsius

    def __repr__(self):
        return f"Temperature({self.celsius}°C)"

t1 = Temperature(100)
t2 = Temperature(50)

t1 == t2   # False
t1 > t2    # True  - auto-generated by @total_ordering
t1 < t2    # False
t1 >= t2   # True

# Sort a list of Temperature objects
temps = [Temperature(30), Temperature(10), Temperature(20)]
sorted(temps)   # [Temperature(10°C), Temperature(20°C), Temperature(30°C)]
```

## Arithmetic Operators

```python
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    def __sub__(self, other):
        return Vector(self.x - other.x, self.y - other.y)

    def __mul__(self, scalar):
        return Vector(self.x * scalar, self.y * scalar)

    def __rmul__(self, scalar):
        """Called when scalar * vector (left operand doesn't support it)"""
        return self.__mul__(scalar)

    def __neg__(self):
        return Vector(-self.x, -self.y)

    def __abs__(self):
        return (self.x**2 + self.y**2) ** 0.5

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

v1 = Vector(1, 2)
v2 = Vector(3, 4)

v1 + v2    # Vector(4, 6)
v1 - v2    # Vector(-2, -2)
v1 * 3     # Vector(3, 6)
3 * v1     # Vector(3, 6)  - uses __rmul__
-v1        # Vector(-1, -2)
abs(v2)    # 5.0
```

## Container Methods

```python
class Stack:
    def __init__(self):
        self._items = []

    def push(self, item):
        self._items.append(item)

    def pop(self):
        return self._items.pop()

    def __len__(self):
        """Called by len()"""
        return len(self._items)

    def __getitem__(self, index):
        """Called by stack[index]"""
        return self._items[index]

    def __setitem__(self, index, value):
        """Called by stack[index] = value"""
        self._items[index] = value

    def __delitem__(self, index):
        """Called by del stack[index]"""
        del self._items[index]

    def __contains__(self, item):
        """Called by 'item in stack'"""
        return item in self._items

    def __iter__(self):
        """Called by for loops and iter()"""
        return iter(self._items)

    def __repr__(self):
        return f"Stack({self._items})"

s = Stack()
s.push(1); s.push(2); s.push(3)

len(s)          # 3
s[0]            # 1
2 in s          # True
for x in s:
    print(x)    # 1 2 3
```

## Callable Objects

```python
class Multiplier:
    def __init__(self, factor):
        self.factor = factor

    def __call__(self, value):
        """Makes the object callable like a function"""
        return value * self.factor

double = Multiplier(2)
triple = Multiplier(3)

double(5)    # 10  - calls double.__call__(5)
triple(5)    # 15

callable(double)   # True
```

## Context Manager Methods

```python
class Timer:
    import time

    def __enter__(self):
        """Called at the start of 'with' block"""
        self.start = __import__('time').time()
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        """Called at the end of 'with' block"""
        self.elapsed = __import__('time').time() - self.start
        print(f"Elapsed: {self.elapsed:.4f}s")
        return False   # don't suppress exceptions

with Timer() as t:
    total = sum(range(1_000_000))
# Elapsed: 0.0421s
```

## Hashing

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

    def __hash__(self):
        """Required to use object as dict key or set member.
        If you define __eq__, you must also define __hash__."""
        return hash((self.x, self.y))

p1 = Point(1, 2)
p2 = Point(1, 2)

p1 == p2            # True
p1 is p2            # False
hash(p1) == hash(p2)  # True

# Can now use in sets and as dict keys
points = {p1, p2}   # set - {Point(1,2)} - deduplicated because __hash__ + __eq__
d = {p1: "origin"}  # dict key
```

## Interview Questions

**Q: What is the difference between `__str__` and `__repr__`?**
`__str__` returns a human-readable string - shown by `print()` and `str()`. `__repr__` returns a developer-readable string - shown in the REPL and by `repr()`. Convention: `__repr__` should ideally produce a string that could recreate the object. If `__str__` is not defined, Python falls back to `__repr__`.

**Q: What is `__call__`?**
`__call__` makes an instance callable like a function. When you do `obj(args)`, Python calls `obj.__call__(args)`. Useful for stateful callables - objects that behave like functions but remember state between calls.

**Q: If you define `__eq__`, do you need to define `__hash__`?**
Yes. Defining `__eq__` without `__hash__` makes Python set `__hash__` to `None`, making your object unhashable (can't be used in sets or as dict keys). If two objects are equal, they must have the same hash. Define `__hash__` using a tuple of the same fields used in `__eq__`.

**Q: What is `__new__` vs `__init__`?**
`__new__` creates and returns the new instance (called first). `__init__` initializes the instance after it's been created (called second). You rarely override `__new__` - only for Singleton patterns or when subclassing immutable types like `int` or `str`.

**Q: What does `@total_ordering` do?**
It's a decorator from `functools` that auto-generates the remaining comparison methods (`__le__`, `__gt__`, `__ge__`) from just `__eq__` and one of `__lt__` or `__gt__`. Saves you from writing all six comparison methods manually.

## Summary

- Dunder methods let classes integrate with Python's built-in syntax and functions
- `__str__` - human output; `__repr__` - developer output; always define `__repr__` at minimum
- `__len__`, `__getitem__`, `__contains__`, `__iter__` - make objects behave like containers
- `__add__`, `__sub__`, `__mul__` - operator overloading; `__radd__` for right-hand operations
- `__call__` - makes objects callable like functions
- `__enter__` / `__exit__` - context manager protocol for `with` statement
- `__eq__` + `__hash__` - always define together; needed for use in sets and as dict keys
- `@total_ordering` - define `__eq__` + one comparison, get all six automatically

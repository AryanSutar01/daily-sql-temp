## Why Transformation Performance Matters

When you transform a pandas DataFrame with 10 million rows, the difference between the right approach and the wrong approach can be the difference between a 2-second operation and a 5-minute wait. In production ETL pipelines, data transformations often run on millions to billions of rows. Choosing the wrong method doesn't just slow down your script — it can make a pipeline miss its SLA window.

The root cause of performance differences is **where the computation happens**:

```
Vectorized operations   → C code via NumPy; entire array in one C call
map()                   → Python function called per element (fast due to simpler dispatch)
apply(axis=0 or 1)      → Python function called per row/column; full Python interpreter overhead per call
```

For 1 million rows:
- A vectorized operation does **1 C function call**
- `apply()` does **1,000,000 Python function calls** — each with function call overhead, argument packing, and Python object creation

Python's function call overhead is not trivial. Each call requires building a stack frame, resolving the function in the namespace, marshalling arguments, and cleaning up — all in the CPython interpreter at ~10–100 million operations per second. C code runs at billions of operations per second with SIMD acceleration.

```
Method              Applies to          Speed       Use when
------              ----------          -----       ---------
Vectorized ops      Series / column     Fastest     Simple math, string ops, comparisons
map()               Series              Fast        Element-wise — replace values or apply function
apply()             Series or DataFrame Slower      Complex logic involving multiple columns
applymap() / map()  DataFrame           Slowest     Element-wise across entire DataFrame
```

## Vectorized Operations — Always Try First

Vectorized operations delegate computation entirely to NumPy, which calls optimized BLAS/LAPACK libraries and uses SIMD (Single Instruction, Multiple Data) CPU instructions to process multiple elements simultaneously. The Python interpreter participates exactly once — to dispatch the operation.

```python
import pandas as pd
import numpy as np

df = pd.DataFrame({
    "salary": [70000, 85000, 92000, 65000, 78000],
    "age": [25, 30, 35, 28, 32],
    "name": ["alice smith", "bob jones", "carol white", "dave brown", "eve black"],
})

# Arithmetic — vectorized
df["salary_monthly"] = df["salary"] / 12
df["salary_with_bonus"] = df["salary"] * 1.1
df["salary_diff_from_mean"] = df["salary"] - df["salary"].mean()

# Comparisons — vectorized (produce a boolean Series)
df["is_senior"] = df["age"] >= 30
df["high_earner"] = df["salary"] > 80000

# String operations — vectorized via .str accessor (no Python loop)
df["name_upper"] = df["name"].str.upper()
df["first_name"] = df["name"].str.split().str[0]
df["name_length"] = df["name"].str.len()

# numpy where — vectorized conditional (if/else for arrays)
df["level"] = np.where(df["salary"] > 80000, "Senior", "Junior")

# np.select — vectorized if/elif/else for multiple conditions
conditions = [
    df["salary"] > 90000,
    df["salary"] > 75000,
]
choices = ["Lead", "Senior"]
df["grade"] = np.select(conditions, choices, default="Junior")
```

**The `.str` accessor** is particularly important: it vectorizes string operations that would otherwise require a Python loop. `df["name"].str.upper()` calls C code for every element — it is not a Python loop in disguise. It is equivalent to calling NumPy on strings.

## map() — Element-wise on a Series

`map()` applies a function or dictionary to each element of a Series. It is faster than `apply()` because it avoids the overhead of constructing a full row object, but it still calls Python per element for function-based mapping.

```python
# Dict mapping — pure C lookup, extremely fast
dept_codes = {1: "Engineering", 2: "Marketing", 3: "HR"}
df["dept_name"] = df["dept_id"].map(dept_codes)
# NaN for keys not in the dict — handle with .fillna()
df["dept_name"] = df["dept_id"].map(dept_codes).fillna("Unknown")

# Function-based mapping
df["salary_k"] = df["salary"].map(lambda x: f"₹{x/1000:.0f}k")

# With a built-in function (faster than lambda — no Python frame creation)
df["name_title"] = df["name"].map(str.title)
```

**Dict-based `map()` is very fast** because the lookup happens in C via Python's dictionary hash table — it does not call Python per element. Function-based `map()` still calls Python per element but is slightly faster than `apply()` because it avoids the overhead of creating a Series object for each row.

## apply() — Custom Logic on Series or DataFrame

`apply()` is the escape hatch for logic that cannot be expressed with vectorized operations or `map()`. It is the most flexible but slowest approach.

### apply on a Series (column)

```python
def categorize_salary(salary):
    if salary > 90000:
        return "High"
    elif salary > 75000:
        return "Medium"
    else:
        return "Low"

# This is ~100x slower than np.select for the same logic
df["salary_band"] = df["salary"].apply(categorize_salary)

# The vectorized equivalent — always prefer this
conditions = [df["salary"] > 90000, df["salary"] > 75000]
df["salary_band"] = np.select(conditions, ["High", "Medium"], default="Low")
```

### apply on DataFrame rows (axis=1)

```python
# Access multiple columns in one function
def compute_score(row):
    return row["salary"] / 1000 + (row["age"] - 20) * 2

df["score"] = df.apply(compute_score, axis=1)
# This calls compute_score once per row — 5 calls for 5 rows, 1M calls for 1M rows

# Vectorized equivalent — always prefer this
df["score"] = df["salary"] / 1000 + (df["age"] - 20) * 2
```

`apply(axis=1)` is the slowest common pandas operation. Each row is constructed as a Python `Series` object (with its own index), passed to your function, and the result unwrapped — massive overhead per row.

### apply returning multiple values

```python
# One legitimate use of apply: when you need to return multiple new columns
def parse_name(name):
    parts = name.split()
    return pd.Series({"first": parts[0], "last": parts[-1]})

df[["first_name", "last_name"]] = df["name"].apply(parse_name)

# But the vectorized alternative is still better:
name_parts = df["name"].str.split()
df["first_name"] = name_parts.str[0]
df["last_name"] = name_parts.str[-1]
```

## Performance Benchmark

```python
import time
import pandas as pd
import numpy as np

df = pd.DataFrame({"salary": np.random.randint(50000, 150000, 1_000_000)})

# apply — 1 Python function call per element
start = time.time()
df["cat"] = df["salary"].apply(lambda x: "High" if x > 100000 else "Low")
print(f"apply:      {time.time() - start:.3f}s")   # ~2.1s

# map — same call overhead but lighter dispatch
start = time.time()
df["cat"] = df["salary"].map(lambda x: "High" if x > 100000 else "Low")
print(f"map:        {time.time() - start:.3f}s")   # ~1.8s

# np.where — 1 C function call for all 1M elements
start = time.time()
df["cat"] = np.where(df["salary"] > 100000, "High", "Low")
print(f"np.where:   {time.time() - start:.3f}s")   # ~0.02s

# Typical results:
# apply:    2.1s
# map:      1.8s
# np.where: 0.02s   ← 100x faster than apply
```

**The performance gap scales with data size**. For 10,000 rows, `apply()` finishes in milliseconds and the difference is unnoticeable. For 10 million rows, the same `apply()` takes minutes while `np.where` takes under a second. Always benchmark on realistic data sizes.

## When to Use Each — Decision Guide

```python
# USE vectorized ops when:
# — Simple math, comparisons, string ops on a column
df["tax"] = df["salary"] * 0.3
df["name_clean"] = df["name"].str.strip().str.lower()
df["level"] = np.where(df["salary"] > 80000, "Senior", "Junior")

# USE map() when:
# — Replacing values with a dict lookup
# — Applying a simple element-wise function to a Series
df["dept"] = df["dept_id"].map({1: "Eng", 2: "Mkt"})
df["label"] = df["score"].map(lambda x: f"{x:.2f}")

# USE apply() ONLY when:
# — Logic is genuinely too complex for vectorized operations
# — You need to access multiple columns with non-trivial conditional logic
# — Logic requires calling an external service or has side effects

# NEVER use apply() for:
# — Simple arithmetic (df["a"] + df["b"])
# — Simple conditions (np.where, np.select)
# — String methods (str.upper(), str.contains())
```

## Practical Example — ETL Transformation Pipeline

This example demonstrates the principle of using the fastest available method for each type of operation in a realistic data transformation.

```python
import pandas as pd
import numpy as np

raw = pd.DataFrame({
    "user_id": [1, 2, 3, 4, 5],
    "full_name": ["  Alice Smith ", "BOB JONES", "carol WHITE", None, "EVE BLACK"],
    "salary_str": ["70,000", "85,000", "92,000", "65,000", "N/A"],
    "dept_code": ["ENG", "MKT", "ENG", "HR", "MKT"],
})

# Vectorized string cleaning — no apply() needed
raw["full_name"] = raw["full_name"].str.strip().str.title().fillna("Unknown")

# Parse salary with map() — handles exceptions per element
def parse_salary(s):
    try:
        return float(s.replace(",", ""))
    except (ValueError, AttributeError):
        return np.nan

raw["salary"] = raw["salary_str"].map(parse_salary)
raw["salary"] = raw["salary"].fillna(raw["salary"].median())

# Dict mapping — pure C lookup, no Python function call per element
dept_map = {"ENG": "Engineering", "MKT": "Marketing", "HR": "Human Resources"}
raw["department"] = raw["dept_code"].map(dept_map)

# np.select — vectorized multi-condition classification
raw["salary_band"] = np.select(
    [raw["salary"] > 90000, raw["salary"] > 75000],
    ["High", "Medium"],
    default="Low",
)

print(raw[["user_id", "full_name", "salary", "department", "salary_band"]])
```

## Interview Questions

**Q: What is the performance difference between `apply` and vectorized operations, and why?**
`apply` calls a Python function once per element or row — for 1 million rows, that's 1 million Python function calls, each with full interpreter overhead (stack frame creation, argument marshalling, namespace lookup). Vectorized operations call a single C function that processes the entire array using SIMD instructions. The difference is typically 10–100x. On large datasets (10M+ rows), this is the difference between seconds and minutes.

**Q: When is `apply` the right choice?**
`apply` is appropriate when the transformation logic is genuinely complex: it requires multiple columns with conditional logic that cannot be expressed with `np.select`, it needs to call an external function or service per row, or it returns multiple new columns. The key test: if you can replace the `apply` with `np.where`, `np.select`, or `.str.*` operations, you always should.

**Q: What is the difference between `map` and `apply` on a Series?**
Both work element-wise on a Series. `map` additionally accepts a **dictionary** — dict-based `map` is very fast because the lookup happens in C with no Python function call per element. `apply` only accepts a function. For dict-based value replacement, always use `map()`. For element-wise functions, `map()` is slightly faster than `apply()` due to lighter dispatch overhead.

**Q: What is `np.select` and when do you use it?**
`np.select(conditions, choices, default)` is the vectorized equivalent of an if/elif/else chain applied to a whole array. It evaluates all conditions as boolean arrays in C and selects the corresponding choice for each element. Use it whenever you have 2+ conditions — it replaces `apply()` with nested `if` statements and is typically 50–100x faster.

**Q: How would you identify which operations are bottlenecks in a pandas pipeline?**
Profile with `%timeit` (Jupyter) or `timeit.timeit()` in scripts. Look for `apply()` calls on large DataFrames first. Use `df.memory_usage()` to check if `object` dtype columns should be `category`. Consider `swifter` (Dask-based parallel apply) for genuinely complex per-row operations that can't be vectorized.

## Summary

- **Vectorization first**: `df["col"] * 2`, `np.where()`, `np.select()`, `.str.*` — all run in C
- **`np.where(cond, a, b)`** — vectorized if-else; `np.select(conditions, choices, default)` — vectorized if/elif/else
- **`map(dict)`** — dict-based value replacement; C-speed hash table lookups, no Python calls per element
- **`map(func)`** — element-wise function on a Series; slightly faster than `apply` for simple functions
- **`apply()`** — 1 Python call per element/row; 10–100x slower; use only when vectorized alternatives don't exist
- `apply(axis=1)` — worst case: constructs a full Series per row; avoid for large DataFrames
- The performance gap scales: negligible at 10K rows, critical at 10M rows
- Profile on realistic data sizes — always benchmark before deciding apply() is acceptable

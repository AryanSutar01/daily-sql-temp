## Why Not Just Use print()?

`print()` is fine for quick checks but has serious limitations in real projects:

```
print()                         logging
-------                         -------
No severity levels              DEBUG, INFO, WARNING, ERROR, CRITICAL
No timestamps                   Timestamps built-in
No context (file, line)         File name, line number, function name
Can't filter easily             Filter by level, module, logger name
Hard to disable in production   Set level to WARNING in prod, DEBUG in dev
No file output                  Write to file, stream, email, etc.
```

## Python's logging Module

```python
import logging

# Basic config - simplest setup
logging.basicConfig(level=logging.DEBUG)

logging.debug("Detailed info for debugging")
logging.info("General info about program execution")
logging.warning("Something unexpected happened")
logging.error("A serious problem occurred")
logging.critical("A fatal error - program may not continue")

# Output:
# DEBUG:root:Detailed info for debugging
# INFO:root:General info about program execution
# WARNING:root:Something unexpected happened
# ERROR:root:A serious problem occurred
# CRITICAL:root:A fatal error - program may not continue
```

## Log Levels

```
Level       Value   When to use
-----       -----   -----------
DEBUG       10      Detailed diagnostics - only during development
INFO        20      Confirming things work as expected
WARNING     30      Something unexpected, but program still runs (default level)
ERROR       40      A function failed, but program continues
CRITICAL    50      Serious error - program may not continue
```

```python
# Only messages at or above the configured level are output
logging.basicConfig(level=logging.WARNING)

logging.debug("Won't show")    # below WARNING
logging.info("Won't show")     # below WARNING
logging.warning("Will show")   # at WARNING
logging.error("Will show")     # above WARNING
```

## Proper Logger Setup

Using the root logger (`logging.info(...)`) is fine for scripts but causes issues in packages. Use named loggers:

```python
import logging

logger = logging.getLogger(__name__)   # __name__ = module name

def process_order(order_id: int):
    logger.info(f"Processing order {order_id}")
    try:
        # ... processing logic
        logger.debug(f"Order {order_id} validated")
    except ValueError as e:
        logger.error(f"Validation failed for order {order_id}: {e}")
        raise
```

## Formatting Log Messages

```python
import logging

logging.basicConfig(
    level=logging.DEBUG,
    format="%(asctime)s | %(levelname)-8s | %(name)s | %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S",
)

logger = logging.getLogger(__name__)
logger.info("Application started")
# 2024-03-15 10:30:45 | INFO     | __main__ | Application started
```

### Common Format Variables

```python
%(asctime)s      # human-readable timestamp
%(levelname)s    # DEBUG, INFO, WARNING, etc.
%(name)s         # logger name (__name__ of the module)
%(message)s      # the log message
%(filename)s     # source file name
%(lineno)d       # line number
%(funcName)s     # function name
%(process)d      # process ID
%(thread)d       # thread ID
```

## Logging to a File

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s | %(levelname)s | %(message)s",
    handlers=[
        logging.FileHandler("app.log"),       # write to file
        logging.StreamHandler(),              # also print to console
    ]
)

logger = logging.getLogger(__name__)
logger.info("This goes to both console and file")
```

## Advanced Setup with Handlers

```python
import logging

def setup_logger(name: str, log_file: str, level=logging.DEBUG):
    logger = logging.getLogger(name)
    logger.setLevel(level)

    formatter = logging.Formatter(
        "%(asctime)s | %(levelname)-8s | %(name)s:%(lineno)d | %(message)s"
    )

    # File handler - DEBUG and above
    fh = logging.FileHandler(log_file)
    fh.setLevel(logging.DEBUG)
    fh.setFormatter(formatter)

    # Console handler - WARNING and above only
    ch = logging.StreamHandler()
    ch.setLevel(logging.WARNING)
    ch.setFormatter(formatter)

    logger.addHandler(fh)
    logger.addHandler(ch)

    return logger

logger = setup_logger("myapp", "myapp.log")
logger.debug("Only in file")
logger.warning("In both file and console")
```

## Logging Exceptions

```python
import logging

logger = logging.getLogger(__name__)

def divide(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        logger.exception("Division by zero")   # logs ERROR with full traceback
        return None
    except Exception as e:
        logger.error(f"Unexpected error: {e}", exc_info=True)   # same as exception()
        raise

divide(10, 0)
# ERROR:__main__:Division by zero
# Traceback (most recent call last):
#   File "...", line 6, in divide
#     return a / b
# ZeroDivisionError: division by zero
```

## Debugging with pdb

Python's built-in debugger lets you pause execution and inspect state interactively.

```python
import pdb

def buggy_function(data):
    result = []
    for item in data:
        pdb.set_trace()    # execution pauses here
        processed = item * 2
        result.append(processed)
    return result
```

### Common pdb Commands

```
n (next)       - execute next line (step over)
s (step)       - step into function call
c (continue)   - continue until next breakpoint
l (list)       - show current code
p expr         - print value of expression (e.g. p item)
pp expr        - pretty-print
b 15           - set breakpoint at line 15
q (quit)       - quit debugger
h (help)       - show all commands
```

### Python 3.7+ - breakpoint()

```python
def process(data):
    for item in data:
        breakpoint()   # cleaner than pdb.set_trace()
        result = item * 2
    return result

# Disable all breakpoints in production
import os
os.environ["PYTHONBREAKPOINTHOOK"] = "0"
```

## Debugging Tips Without a Debugger

```python
import traceback

# Print full traceback anywhere
try:
    risky_code()
except Exception:
    traceback.print_exc()   # full traceback to stderr
    # or
    tb = traceback.format_exc()
    logger.error(f"Error occurred:\n{tb}")

# Inspect variable types quickly
def debug_vars(**kwargs):
    for name, value in kwargs.items():
        print(f"{name}: {type(value).__name__} = {value!r}")

debug_vars(x=42, name="Alice", items=[1, 2, 3])
# x: int = 42
# name: str = 'Alice'
# items: list = [1, 2, 3]
```

## Practical Real-World Logger

```python
import logging
import sys
from pathlib import Path

def get_logger(name: str) -> logging.Logger:
    logger = logging.getLogger(name)

    if logger.handlers:   # avoid adding duplicate handlers
        return logger

    logger.setLevel(logging.DEBUG)

    fmt = logging.Formatter(
        "%(asctime)s | %(levelname)-8s | %(name)s | %(message)s",
        datefmt="%Y-%m-%d %H:%M:%S",
    )

    # Console - INFO and above
    console = logging.StreamHandler(sys.stdout)
    console.setLevel(logging.INFO)
    console.setFormatter(fmt)

    # File - DEBUG and above
    log_dir = Path("logs")
    log_dir.mkdir(exist_ok=True)
    file_handler = logging.FileHandler(log_dir / f"{name}.log")
    file_handler.setLevel(logging.DEBUG)
    file_handler.setFormatter(fmt)

    logger.addHandler(console)
    logger.addHandler(file_handler)
    return logger

# Usage in any module
logger = get_logger(__name__)
logger.info("Service started")
logger.debug("Config loaded: %s", {"host": "localhost"})
```

## Interview Questions

**Q: What are the logging levels in Python and when do you use each?**
DEBUG (10) for detailed diagnostics; INFO (20) for normal operations; WARNING (30, default) for unexpected but non-breaking issues; ERROR (40) for failures; CRITICAL (50) for fatal errors. In production you typically set the level to INFO or WARNING to avoid noise.

**Q: Why use `logging` instead of `print()`?**
`logging` provides severity levels, timestamps, caller info, filtering, and multiple output destinations (file, console, remote). Unlike `print`, you can turn off or filter logs without touching the code - just change the log level.

**Q: What is `logger.exception()` and when do you use it?**
`logger.exception()` logs an ERROR message and automatically includes the full traceback of the current exception. Use it inside `except` blocks when you want to log the error with its full stack trace.

**Q: What is `pdb` and how do you use it?**
`pdb` is Python's built-in interactive debugger. Insert `breakpoint()` (Python 3.7+) or `pdb.set_trace()` in your code to pause execution at that point. You can then step through code, inspect variables, and evaluate expressions interactively.

**Q: What does `getLogger(__name__)` do?**
It creates a logger named after the current module. This lets you filter, configure, and identify log messages by module. It's best practice - the root logger (`logging.info()`) is shared globally and can cause conflicts in larger projects.

## Summary

- Use **named loggers** (`logging.getLogger(__name__)`) - never rely solely on the root logger
- Five levels: `DEBUG < INFO < WARNING < ERROR < CRITICAL` - only messages at or above the configured level are shown
- Use `basicConfig()` for simple scripts; use `Handler` + `Formatter` for production setups
- `logger.exception()` logs an error with the full traceback - use inside `except` blocks
- Use multiple handlers to send DEBUG to file and WARNING+ to console simultaneously
- `breakpoint()` / `pdb.set_trace()` - pause execution and inspect state interactively
- `traceback.format_exc()` - capture full traceback as a string for logging

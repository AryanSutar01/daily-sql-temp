## Abstract Base Classes: Structural Contracts and Interface Enforcement in Python

In large-scale, enterprise software systems, you frequently need to enforce rigid structural contracts. An **Abstract Base Class (ABC)** is an architectural blueprint that **cannot be instantiated**. It forces any subclass to implement specific methods, guaranteeing a uniform API across disparate child classes (e.g., ensuring every database driver implements a `connect()` method).

Python relies on the `abc` module and the `ABCMeta` metaclass to enforce this architecture dynamically at runtime.

### The CPython Mechanics of `ABCMeta`

How does Python physically prevent you from instantiating an abstract class?

When you define a class that inherits from `ABC`, Python assigns it a special metaclass called `ABCMeta`. During class construction, `ABCMeta` scans the class's dictionary for any methods decorated with `@abstractmethod`. 

Under the hood, `@abstractmethod` is a simple decorator that sets a C-level flag on the function object: `__isabstractmethod__ = True`. 

If `ABCMeta` finds any method with this flag, it adds the method's name to a special internal frozenset attribute called `__abstractmethods__`. When you attempt to instantiate the class via `__call__`, the CPython interpreter checks the `__abstractmethods__` set. If the set is not empty, the interpreter immediately throws a `TypeError` and blocks memory allocation.

```python
from abc import ABC, abstractmethod

class DatabaseDriver(ABC):
    @abstractmethod
    def connect(self) -> bool:
        ... # The contract demands this method exists, but provides no implementation

# Python physically prevents instantiation because DatabaseDriver.__abstractmethods__ 
# contains {'connect'}
# db = DatabaseDriver() # TypeError: Can't instantiate abstract class
```

## Enforcing the Contract on Subclasses

When a class inherits from an `ABC`, it is legally bound to implement every abstract method. If it fails to do so, it inherits the `__abstractmethods__` set from its parent. 

If the child class implements the method, `ABCMeta` removes that method name from the child's `__abstractmethods__` set. If the set becomes empty, the class is deemed concrete, and instantiation is permitted.

```python
from abc import ABC, abstractmethod

class DatabaseDriver(ABC):
    @abstractmethod
    def connect(self) -> bool: ...

class PostgresDriver(DatabaseDriver):
    def connect(self) -> bool:
        print("Connected to PostgreSQL")
        return True

class MongoDriver(DatabaseDriver):
    # Fails to implement connect()
    pass

pg = PostgresDriver() # Success: __abstractmethods__ is empty
# mongo = MongoDriver() # TypeError: MongoDriver inherits the 'connect' requirement
```

## Hybrid Architectures: Concrete and Abstract

Unlike strict interfaces in languages like Java (prior to default methods), Python's Abstract Base Classes can hold state and provide **concrete methods** alongside abstract ones. This allows developers to share common business logic while enforcing specific behaviors on child implementations.

```python
from abc import ABC, abstractmethod

class Logger(ABC):
    def __init__(self, prefix: str):
        self.prefix = prefix  # State sharing
        
    @abstractmethod
    def write(self, message: str) -> None: ...

    # Concrete method inherited by all subclasses
    def info(self, message: str) -> None:
        # Relies on the child class implementing 'write'
        self.write(f"[INFO] {self.prefix}: {message}")

class ConsoleLogger(Logger):
    def write(self, message: str) -> None:
        print(message) # Implements the missing piece

logger = ConsoleLogger("API")
logger.info("Request received") # Outputs: [INFO] API: Request received
```

## The "Interface" Pattern and Multiple Inheritance

Python lacks a dedicated `interface` keyword. However, architects simulate strict interfaces by creating an `ABC` that contains *only* abstract methods, no `__init__`, and zero state.

Because Python supports Multiple Inheritance, a class can conform to multiple interface contracts simultaneously, heavily utilizing the **Interface Segregation Principle (ISP)** from SOLID design.

```python
class Serializable(ABC):
    @abstractmethod
    def to_json(self) -> str: ...

class Cacheable(ABC):
    @abstractmethod
    def get_cache_key(self) -> str: ...

# User conforms to two independent architectural contracts
class User(Serializable, Cacheable):
    def to_json(self) -> str:
        return '{"user": "admin"}'
        
    def get_cache_key(self) -> str:
        return "user:admin"
```

## Abstract Properties and Decorator Stacking

You can enforce the existence of class attributes by combining `@property` and `@abstractmethod`. 

Architecturally, the order of decorators is strictly mandated by the CPython interpreter: **`@property` must be the outermost decorator**. This is because `@abstractmethod` works on functions, and `@property` converts a function into a descriptor object. If you reverse them, `@abstractmethod` tries to modify a descriptor instead of a function, which fails.

```python
from abc import ABC, abstractmethod

class PaymentGateway(ABC):
    @property
    @abstractmethod
    def transaction_fee(self) -> float: ...

class Stripe(PaymentGateway):
    @property
    def transaction_fee(self) -> float:
        return 0.029
```

## Virtual Subclasses (`register`)

Python's `abc` module supports an incredibly advanced feature known as **Virtual Subclasses**. 

You can use the `register` method of an ABC to declare that a completely unrelated class satisfies the ABC's interface. Python will intercept `issubclass()` and `isinstance()` checks and return `True`, even though there is zero inheritance in the MRO!

```python
class Writable(ABC):
    @abstractmethod
    def write(self, data): pass

class CustomLogger:
    def write(self, data): 
        print(data)

# Register CustomLogger as a virtual subclass of Writable
Writable.register(CustomLogger)

# True, even though CustomLogger does NOT inherit from Writable!
print(issubclass(CustomLogger, Writable)) 
```
This dynamic modification of the type system is powerful but dangerous, as it bypasses the compiler's strict structural enforcement.

## Interview Questions

**Q: How does the Python interpreter physically prevent an abstract class from being instantiated?**
When a class inherits from `ABC`, its metaclass (`ABCMeta`) scans for methods decorated with `@abstractmethod` (which sets the `__isabstractmethod__` flag). The metaclass aggregates these names into a frozenset called `__abstractmethods__`. If this set is not empty, the interpreter's C-level memory allocation routines intercept the instantiation attempt and throw a `TypeError`.

**Q: Can an Abstract Base Class have an `__init__` method?**
Yes. Because Python's `ABC`s allow for shared concrete logic and state (unlike strict interfaces in other languages), you can define an `__init__` method. Subclasses will typically call `super().__init__()` to initialize that shared state, while still being forced to implement the abstract methods.

**Q: What happens if a subclass forgets to implement just one abstract method out of ten?**
The subclass itself becomes abstract. The Python interpreter evaluates completeness at class creation time. It inherits the `__abstractmethods__` set from the parent and only removes the methods it implements. Since the set is not empty (one is missing), attempting to instantiate the subclass will throw a `TypeError` detailing the missing method.

**Q: How does `typing.Protocol` structurally differ from `abc.ABC`?**
`abc.ABC` enforces Nominal Subtyping—a class must explicitly inherit from the ABC, and validation occurs at runtime via metaclasses. `typing.Protocol` enforces Structural Subtyping (Static Duck Typing)—a class does not need to inherit from the Protocol, and validation occurs entirely at compile/analysis time via static tools like Mypy.

**Q: Explain Virtual Subclasses and the `register` method.**
The `register` method allows a developer to dynamically inject an unrelated class into an ABC's type hierarchy. It overrides the behavior of `issubclass()` and `isinstance()` to return `True` for the registered class, even though the class does not exist in the ABC's Method Resolution Order (MRO) and does not inherit from it.

## Summary

- **`ABC` and `ABCMeta`**: The structural tools and metaclass used to define abstract blueprints.
- **`__abstractmethods__`**: The internal CPython set that tracks missing methods and blocks instantiation.
- **Contract Enforcement**: Subclasses must implement every abstract method to clear the `__abstractmethods__` set.
- **Hybrid Design**: `ABC`s can mix shared concrete logic (and state) with enforced abstract contracts.
- **Multiple Inheritance**: Python allows classes to implement multiple abstract "interfaces" (Interface Segregation).
- **Abstract Properties**: Enforced using `@property` stacked strictly above `@abstractmethod`.
- **Virtual Subclasses**: Using `register` to hijack `isinstance()` checks without formal inheritance.

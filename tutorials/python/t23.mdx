## What Is an Abstract Class?

An abstract class is a class that **cannot be instantiated directly** and defines methods that subclasses **must implement**. It acts as a blueprint or contract for a family of related classes.

```python
from abc import ABC, abstractmethod

class Shape(ABC):   # inherit from ABC to make it abstract
    @abstractmethod
    def area(self) -> float:
        ...   # no implementation here

    @abstractmethod
    def perimeter(self) -> float:
        ...

# Cannot instantiate an abstract class directly
s = Shape()   # TypeError: Can't instantiate abstract class Shape
```

## Implementing an Abstract Class

```python
from abc import ABC, abstractmethod
import math

class Shape(ABC):
    @abstractmethod
    def area(self) -> float: ...

    @abstractmethod
    def perimeter(self) -> float: ...

    def describe(self) -> str:
        # concrete method - available to all subclasses
        return f"Area: {self.area():.2f}, Perimeter: {self.perimeter():.2f}"

class Circle(Shape):
    def __init__(self, radius: float):
        self.radius = radius

    def area(self) -> float:
        return math.pi * self.radius ** 2

    def perimeter(self) -> float:
        return 2 * math.pi * self.radius

class Rectangle(Shape):
    def __init__(self, width: float, height: float):
        self.width = width
        self.height = height

    def area(self) -> float:
        return self.width * self.height

    def perimeter(self) -> float:
        return 2 * (self.width + self.height)

c = Circle(5)
r = Rectangle(4, 6)

print(c.describe())   # Area: 78.54, Perimeter: 31.42
print(r.describe())   # Area: 24.00, Perimeter: 20.00

# Polymorphism - treat all shapes uniformly
shapes: list[Shape] = [Circle(3), Rectangle(4, 5), Circle(7)]
for shape in shapes:
    print(shape.area())
```

## Abstract Properties

```python
from abc import ABC, abstractmethod

class Animal(ABC):
    @property
    @abstractmethod
    def sound(self) -> str:
        ...

    @abstractmethod
    def move(self) -> str:
        ...

    def describe(self) -> str:
        return f"I {self.move()} and say '{self.sound}'"

class Dog(Animal):
    @property
    def sound(self) -> str:
        return "woof"

    def move(self) -> str:
        return "run"

class Bird(Animal):
    @property
    def sound(self) -> str:
        return "chirp"

    def move(self) -> str:
        return "fly"

d = Dog()
print(d.describe())   # I run and say 'woof'
```

## Abstract Class vs Interface

Python doesn't have a formal `interface` keyword like Java/C#. In Python, an abstract class with **only** abstract methods (no concrete methods, no state) effectively acts as an interface:

```python
# Python "interface" pattern - all methods abstract, no state
class Serializable(ABC):
    @abstractmethod
    def serialize(self) -> str: ...

    @abstractmethod
    def deserialize(self, data: str) -> None: ...

class Printable(ABC):
    @abstractmethod
    def print_info(self) -> None: ...

# A class can implement multiple "interfaces"
class User(Serializable, Printable):
    def __init__(self, name: str, age: int):
        self.name = name
        self.age = age

    def serialize(self) -> str:
        return f"{self.name},{self.age}"

    def deserialize(self, data: str) -> None:
        self.name, age = data.split(",")
        self.age = int(age)

    def print_info(self) -> None:
        print(f"User: {self.name}, Age: {self.age}")
```

## Concrete Methods in Abstract Classes

Abstract classes can also include **concrete methods** with default behaviour that subclasses can optionally override:

```python
from abc import ABC, abstractmethod

class Logger(ABC):
    @abstractmethod
    def write(self, message: str) -> None: ...

    # Concrete methods - shared behaviour
    def info(self, message: str) -> None:
        self.write(f"[INFO] {message}")

    def error(self, message: str) -> None:
        self.write(f"[ERROR] {message}")

    def warning(self, message: str) -> None:
        self.write(f"[WARNING] {message}")

class FileLogger(Logger):
    def __init__(self, filename: str):
        self.filename = filename

    def write(self, message: str) -> None:
        with open(self.filename, "a") as f:
            f.write(message + "\n")

class ConsoleLogger(Logger):
    def write(self, message: str) -> None:
        print(message)

logger = ConsoleLogger()
logger.info("App started")        # [INFO] App started
logger.error("Something broke")   # [ERROR] Something broke
```

## Checking Subclasses and Instances

```python
from abc import ABC, abstractmethod

class Vehicle(ABC):
    @abstractmethod
    def fuel_type(self) -> str: ...

class Car(Vehicle):
    def fuel_type(self) -> str:
        return "petrol"

class Bicycle(Vehicle):
    def fuel_type(self) -> str:
        return "human power"

c = Car()

print(isinstance(c, Vehicle))    # True - Car is a subclass of Vehicle
print(issubclass(Car, Vehicle))  # True
print(Vehicle.__subclasses__())  # [<class 'Car'>, <class 'Bicycle'>]
```

## Real-World Example - Payment Gateway

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass

@dataclass
class PaymentResult:
    success: bool
    transaction_id: str
    message: str

class PaymentGateway(ABC):
    @abstractmethod
    def charge(self, amount: float, currency: str) -> PaymentResult: ...

    @abstractmethod
    def refund(self, transaction_id: str) -> PaymentResult: ...

    def charge_in_inr(self, amount: float) -> PaymentResult:
        return self.charge(amount, "INR")

class StripeGateway(PaymentGateway):
    def charge(self, amount: float, currency: str) -> PaymentResult:
        # Stripe API call here
        return PaymentResult(True, "stripe_txn_123", f"Charged {currency} {amount}")

    def refund(self, transaction_id: str) -> PaymentResult:
        return PaymentResult(True, transaction_id, "Refunded via Stripe")

class RazorpayGateway(PaymentGateway):
    def charge(self, amount: float, currency: str) -> PaymentResult:
        return PaymentResult(True, "rp_txn_456", f"Charged {currency} {amount}")

    def refund(self, transaction_id: str) -> PaymentResult:
        return PaymentResult(True, transaction_id, "Refunded via Razorpay")

def process_payment(gateway: PaymentGateway, amount: float) -> None:
    result = gateway.charge_in_inr(amount)
    if result.success:
        print(f"Success: {result.message} [{result.transaction_id}]")

process_payment(StripeGateway(), 5000.0)
process_payment(RazorpayGateway(), 2000.0)
```

## Interview Questions

**Q: What is an abstract class and why do we need it?**
An abstract class is a class that cannot be instantiated and defines one or more abstract methods that subclasses must implement. It enforces a contract - guaranteeing that all subclasses provide certain methods - while allowing shared concrete behaviour to be inherited.

**Q: What is the difference between an abstract class and a regular class?**
A regular class can be instantiated directly. An abstract class (using `ABC`) cannot - it's meant to be subclassed. If a subclass doesn't implement all abstract methods, it also becomes abstract and cannot be instantiated.

**Q: Does Python have interfaces?**
Python doesn't have a formal `interface` keyword. The convention is to create an abstract class with only abstract methods and no state - this serves the same purpose as an interface. A class can inherit from multiple such abstract classes.

**Q: What happens if a subclass doesn't implement all abstract methods?**
The subclass itself becomes abstract and also cannot be instantiated. Python raises a `TypeError` when you try to instantiate it.

**Q: What is the difference between `@abstractmethod` and a regular method in an abstract class?**
`@abstractmethod` marks a method as something subclasses must override - no working implementation is provided. A regular method in an abstract class has a concrete implementation that subclasses inherit (and can optionally override).

## Summary

- `ABC` and `@abstractmethod` from the `abc` module define abstract classes
- Abstract classes **cannot be instantiated** directly
- Subclasses **must implement** all abstract methods or they also become abstract
- Abstract classes can mix abstract methods (contract) with concrete methods (shared behaviour)
- Use `@property` + `@abstractmethod` together to define abstract properties
- Python achieves interface-like behaviour by making abstract classes with only abstract methods
- Use `isinstance(obj, AbstractClass)` to check if an object conforms to the contract

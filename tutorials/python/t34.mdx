## What Is Web Scraping?

Web scraping is the process of programmatically extracting data from websites. It converts unstructured HTML content into structured data that can be analyzed, stored in a database, or fed into a data pipeline.

Scraping is a legitimate tool in many professional contexts:
- Aggregating publicly available pricing data for market research
- Monitoring competitor pricing, job postings, or news
- Academic research on publicly available content
- Data collection when an official API does not exist

However, scraping comes with significant legal, ethical, and technical responsibilities that every practitioner must understand before writing a single line of code.

## Ethical and Legal Considerations

Before scraping any website, you must address these questions:

**1. Check `robots.txt`** — This file at `yourdomain.com/robots.txt` is the website's machine-readable policy on what may and may not be crawled. Disregarding `robots.txt` is legally risky and ethically wrong.

```python
import requests

robots = requests.get("https://example.com/robots.txt")
print(robots.text)
# User-agent: *
# Disallow: /admin/
# Disallow: /private/
# Crawl-delay: 10

# Respect Crawl-delay: do not make requests faster than the specified interval
```

**2. Check the Terms of Service** — Many sites explicitly prohibit automated access in their ToS. Violating ToS can result in legal action (notably LinkedIn, Facebook, and Craigslist have sued scrapers).

**3. Rate limit your requests** — Add delays between requests to avoid overloading the server. Hammering a server with thousands of requests per second is the equivalent of a denial-of-service attack. Even if you don't intend harm, you can crash small sites.

**4. Identify yourself** — Set a descriptive `User-Agent` header with contact information. This allows site administrators to contact you if there's a problem.

```python
headers = {
    "User-Agent": "MyDataProject/1.0 (research@university.edu)",
}
```

## BeautifulSoup — Parsing Static HTML

BeautifulSoup parses HTML documents and provides a convenient API for traversing and searching the document tree. It is the right tool for **static HTML** — pages where the content is present in the initial HTML response.

```bash
pip install requests beautifulsoup4 lxml
```

`lxml` is the recommended parser — it is faster and more lenient than the built-in `html.parser` for malformed HTML.

```python
import requests
from bs4 import BeautifulSoup
import time

url = "https://books.toscrape.com/"
headers = {"User-Agent": "MyBot/1.0 (educational project)"}

response = requests.get(url, headers=headers, timeout=10)
response.raise_for_status()

soup = BeautifulSoup(response.text, "lxml")

# Navigate the parse tree
print(soup.title.text)             # page title
print(soup.find("h1").text)        # first h1 element
```

### Finding Elements

BeautifulSoup provides multiple ways to find elements in the document. Understanding when to use each is key to writing maintainable scrapers.

```python
# find() — returns the FIRST matching element (or None)
first_h2 = soup.find("h2")

# find_all() — returns ALL matching elements as a list
all_links = soup.find_all("a")
all_h2s = soup.find_all("h2")

# By class
product_pods = soup.find_all("article", class_="product_pod")
# class_ with underscore — 'class' is a reserved keyword in Python

# By id
sidebar = soup.find("div", id="sidebar")

# By attribute
soup.find("input", attrs={"name": "search", "type": "text"})

# CSS selectors — the most flexible and readable approach
soup.select("article.product_pod h3 a")   # all <a> tags inside <h3> inside article.product_pod
soup.select_one(".product_pod .price_color")  # first match
soup.select("table.stats tr td.value")    # table cells in the stats table
```

**CSS selectors vs find/find_all**: CSS selectors (via `select()`) handle complex traversal patterns concisely and are familiar to anyone who writes CSS. For simple searches, `find_all("tag", class_="name")` is more readable. Use whichever makes the intent clearest.

### Extracting Data

```python
# Text content
element.text          # all text including nested elements
element.get_text()    # equivalent, more explicit
element.get_text(strip=True)           # strip whitespace
element.get_text(separator=" ")       # join nested text with separator

# Attributes
link = soup.find("a")
link["href"]           # raises KeyError if attribute missing
link.get("href")       # returns None if attribute missing (safer)

# Practical extraction example
products = []
for article in soup.select("article.product_pod"):
    title = article.find("h3").find("a").get("title", "No title")
    price = article.find("p", class_="price_color").text.strip()
    rating = article.find("p", class_="star-rating")["class"][1]   # "Three", "Four", etc.
    availability = article.find("p", class_="instock availability").get_text(strip=True)
    
    products.append({
        "title": title,
        "price": price,
        "rating": rating,
        "availability": availability,
    })
```

### Scraping Multiple Pages

```python
import requests
from bs4 import BeautifulSoup
import time

def scrape_all_pages(base_url: str) -> list:
    """Scrape all pages of a paginated site respectfully."""
    all_products = []
    page = 1
    
    with requests.Session() as session:
        session.headers.update({"User-Agent": "MyBot/1.0 (educational)"})
        
        while True:
            url = f"{base_url}/catalogue/page-{page}.html"
            response = session.get(url, timeout=10)
            
            if response.status_code == 404:
                break   # no more pages
            
            response.raise_for_status()
            soup = BeautifulSoup(response.text, "lxml")
            
            for article in soup.select("article.product_pod"):
                # Extract product data...
                all_products.append({})
            
            page += 1
            time.sleep(1.0)   # be respectful — 1 second between requests
    
    return all_products
```

**`time.sleep(1.0)` between requests is not optional** — it is a professional courtesy. Without it, you risk:
1. Getting your IP address banned by the site
2. Causing legitimate users to experience degraded service
3. Violating the site's `robots.txt` `Crawl-delay` directive

## Handling Anti-Scraping Measures

Professional sites employ various techniques to prevent automated access. Understanding these mechanisms helps you write more resilient scrapers and also tells you when scraping is genuinely not welcome.

### Common Anti-Scraping Techniques

```python
# 1. User-Agent checking — server rejects non-browser User-Agents
# Always set a realistic User-Agent
headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",
    "Accept": "text/html,application/xhtml+xml,application/xhtml",
    "Accept-Language": "en-US,en;q=0.9",
    "Accept-Encoding": "gzip, deflate, br",
    "Referer": "https://www.google.com/",
}

# 2. Cookie requirements — some sites require a session cookie from the homepage
session = requests.Session()
session.get("https://example.com/")   # get cookies
data = session.get("https://example.com/data")   # cookies sent automatically

# 3. IP rate limiting — block IPs making too many requests
# Solution: exponential backoff + randomized delays
import random
time.sleep(random.uniform(1.0, 3.0))   # random delay between 1 and 3 seconds

# 4. CAPTCHA — requires human verification (cannot be bypassed ethically)
# If you encounter CAPTCHAs, this is a strong signal the site does not want scraping
# Third-party CAPTCHA solving services exist but raise serious ethical questions
```

### JavaScript-Rendered Content

Many modern sites (React, Vue, Angular) load data dynamically via JavaScript after the initial page load. In this case, `requests` + BeautifulSoup receives an empty shell of HTML — the data you want hasn't been loaded yet.

**How to identify JS-rendered content**: View the page source (not inspect) in your browser. If the content you want is absent from the raw source, it's loaded by JavaScript.

## Selenium — Browser Automation for Dynamic Pages

Selenium automates a real browser — it can click buttons, fill forms, scroll pages, and wait for JavaScript to execute. It is the correct tool for JavaScript-rendered content.

```bash
pip install selenium
# Download ChromeDriver matching your Chrome version from chromedriver.chromium.org
```

```python
from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC
from selenium.webdriver.chrome.options import Options

# Run in headless mode for servers (no visible browser window)
options = Options()
options.add_argument("--headless")
options.add_argument("--no-sandbox")
options.add_argument("--disable-dev-shm-usage")

driver = webdriver.Chrome(options=options)

try:
    driver.get("https://example.com")
    
    # Wait for a specific element to appear (up to 10 seconds)
    # This handles asynchronous JavaScript loading
    wait = WebDriverWait(driver, timeout=10)
    element = wait.until(EC.presence_of_element_located((By.CSS_SELECTOR, ".product-list")))
    
    # Find elements (same CSS selectors as BeautifulSoup)
    products = driver.find_elements(By.CSS_SELECTOR, ".product-card")
    
    for product in products:
        title = product.find_element(By.CSS_SELECTOR, ".title").text
        price = product.find_element(By.CSS_SELECTOR, ".price").text
        print(f"{title}: {price}")
    
    # Click a button
    load_more = driver.find_element(By.ID, "load-more-btn")
    load_more.click()
    
    # Fill a form
    search_input = driver.find_element(By.NAME, "q")
    search_input.send_keys("laptop")
    search_input.submit()

finally:
    driver.quit()   # always close the browser — avoids dangling browser processes
```

### Waiting for Dynamic Content

The most common Selenium error is `NoSuchElementException` because code tries to find an element before JavaScript has rendered it. Always use `WebDriverWait` with explicit conditions instead of `time.sleep`.

```python
from selenium.webdriver.support import expected_conditions as EC

# Explicit wait — preferred over time.sleep()
wait = WebDriverWait(driver, timeout=15)

# Wait for element to be present in DOM
wait.until(EC.presence_of_element_located((By.ID, "results")))

# Wait for element to be visible (present AND visible)
wait.until(EC.visibility_of_element_located((By.CSS_SELECTOR, ".data-table")))

# Wait for text to appear in element
wait.until(EC.text_to_be_present_in_element((By.ID, "status"), "Complete"))

# Wait for URL to change (after form submit or redirect)
wait.until(EC.url_contains("/results"))
```

**`time.sleep()` is fragile**: if the network is slow, your fixed sleep may not be enough; if it's fast, you waste time. Explicit waits are both more reliable and faster.

## BeautifulSoup vs Selenium — When to Use Which

```
BeautifulSoup + requests:
  ✓ Static HTML (content in page source)
  ✓ Fast — no browser overhead
  ✓ Low resource usage — can run on minimal servers
  ✓ Good for large-scale scraping (thousands of pages)
  ✗ Cannot execute JavaScript
  ✗ Cannot interact with the page (click, scroll, form fill)

Selenium:
  ✓ JavaScript-rendered content
  ✓ Pages requiring interaction (login, infinite scroll, AJAX)
  ✓ CAPTCHA bypass (human-in-the-loop)
  ✗ Slow — launches a real browser
  ✗ High resource usage (hundreds of MB per browser instance)
  ✗ Harder to scale without a browser farm

Alternative for JS-rendered content: Playwright (modern Selenium alternative)
  pip install playwright
  playwright install chromium
```

## Interview Questions

**Q: What is the difference between BeautifulSoup and Selenium?**
BeautifulSoup parses static HTML — the HTML you receive in the HTTP response. It's fast and lightweight but cannot execute JavaScript. Selenium automates a real browser (Chrome, Firefox), executes JavaScript, and can interact with the page (click, scroll, fill forms). Use BeautifulSoup for static pages where content is in the raw HTML; use Selenium when content is loaded dynamically by JavaScript after the initial page load.

**Q: Why should you add delays between scraping requests?**
Without delays, you send requests as fast as your network and CPU allow — potentially thousands per second. This can crash small websites, degrade service for real users, and trigger IP bans. `robots.txt` often specifies a `Crawl-delay` value. Respecting it by adding `time.sleep()` is both legally safer and ethically required.

**Q: How would you scrape a site that requires login?**
Use a `requests.Session`. First, submit the login form with `session.post(login_url, data={...})`. The session automatically stores the authentication cookies. Subsequent requests in the same session automatically send those cookies, maintaining the authenticated session.

**Q: What is an explicit wait in Selenium and why is it better than `time.sleep`?**
An explicit wait (`WebDriverWait` + `expected_conditions`) polls the DOM condition every 500ms until it becomes true, up to a maximum timeout. `time.sleep(5)` always waits exactly 5 seconds regardless of when the element appears. Explicit waits are faster (return as soon as the condition is met) and more reliable (don't fail on slow networks where a fixed sleep might not be enough).

**Q: How do you identify whether a page uses static HTML or JavaScript rendering?**
Right-click the page in your browser and select "View Page Source" (not Inspect). If the data you want to scrape is present in the raw source, the page is statically rendered — use BeautifulSoup. If the raw source is mostly empty template HTML (with `<div id="root">` or `<script>` tags), the content is loaded by JavaScript — use Selenium or Playwright.

## Summary

- Always check `robots.txt` and Terms of Service before scraping
- Set a descriptive `User-Agent` header; add `time.sleep()` between requests
- **BeautifulSoup** — parse static HTML; `find()` (first), `find_all()` (all), `select()` (CSS selector)
- `element.get("href")` — safe attribute access (returns None); `element["href"]` raises KeyError
- `element.get_text(strip=True)` — extract clean text content
- Use `requests.Session()` for connection pooling and cookie persistence across pages
- **Selenium** — browser automation for JavaScript-rendered pages
- `WebDriverWait` + `EC.presence_of_element_located()` — always use explicit waits over `time.sleep()`
- `driver.quit()` in a `finally` block — always close the browser to release resources
- Save scraped data to CSV or parquet via pandas for downstream analysis

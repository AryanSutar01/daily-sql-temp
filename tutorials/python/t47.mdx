## The Assignment Aliasing Problem

The most fundamental thing to understand about copying in Python is that **assignment (`=`) never copies an object**. It creates a new name that points to the same object in memory. For immutable types (integers, strings), this is safe — they can't be changed. For mutable types (lists, dicts, custom objects), this creates an **alias**: two names pointing at the same object, where mutations through either name affect both.

```python
# The illusion of copying
original = [1, 2, 3]
alias = original       # NOT a copy — two names, one object

print(id(original) == id(alias))   # True — same memory address

alias.append(4)
print(original)   # [1, 2, 3, 4] — original changed because it IS alias
print(alias)      # [1, 2, 3, 4]

# Reassigning alias doesn't affect original — it just rebinds the name
alias = [10, 20]
print(original)   # [1, 2, 3, 4] — original still points to the old object
```

This behaviour is intentional and efficient — Python doesn't copy objects by default because copies are expensive and often unnecessary. But it means you must be explicit when you want independence.

## Shallow Copy — New Container, Shared Contents

A shallow copy creates a **new container object** at a different memory address, but the elements inside it still reference the same objects as the original. For flat structures (a list of numbers, a dict of strings), this is usually sufficient — the elements are immutable and can't be modified anyway. For nested structures (a list of lists, a dict containing lists), shallow copy is often a trap.

```python
import copy

original = [1, 2, 3]
shallow = copy.copy(original)   # new list object, same integer elements

print(id(original) == id(shallow))      # False — different container objects
print(id(original[0]) == id(shallow[0]))  # True — same element objects

shallow.append(4)       # modifies only shallow's container
print(original)         # [1, 2, 3] — unaffected ✓
print(shallow)          # [1, 2, 3, 4]
```

Where shallow copy breaks down is with nested mutable objects. The outer container is new, but the inner objects are still shared:

```python
nested = [[1, 2], [3, 4], [5, 6]]
shallow = copy.copy(nested)

# The outer lists are different objects
print(id(nested) == id(shallow))        # False — different outer lists ✓

# But the inner lists are the SAME objects
print(id(nested[0]) == id(shallow[0])) # True — shared inner list ✗

shallow[0].append(99)       # modifies the shared inner list
print(nested[0])            # [1, 2, 99] — original affected ✗
print(shallow[0])           # [1, 2, 99] — same object

# Replacing the inner list in shallow doesn't affect nested
shallow[0] = [100, 200]     # rebinds shallow[0] to a new object
print(nested[0])            # [1, 2, 99] — nested[0] unchanged ✓
```

Think of a shallow copy as: "copy the container, but share the contents."

### Ways to Make a Shallow Copy

Python provides multiple equivalent ways to shallow copy, each with different syntactic convenience:

```python
lst = [1, [2, 3], 4]

# All four are equivalent shallow copies
import copy
a = copy.copy(lst)        # explicit, works for any object
b = lst.copy()            # list method — cleanest for lists
c = lst[:]                # slice syntax — Pythonic shorthand
d = list(lst)             # constructor — also works for other iterables

# For dicts — equivalent shallow copies
d = {"a": [1, 2], "b": [3, 4]}
shallow_d1 = d.copy()        # dict method
shallow_d2 = dict(d)          # constructor
shallow_d3 = {**d}            # unpacking — also a shallow copy
# All share the same inner lists [1,2] and [3,4]
```

## Deep Copy — Full Recursive Independence

A deep copy recursively copies **everything** — the outer container, every inner object, every nested object within those, down to the leaves. The result is completely independent from the original: no shared references at any level.

```python
import copy

nested = [[1, 2], [3, 4], [5, 6]]
deep = copy.deepcopy(nested)

# Both the outer container AND inner objects are different
print(id(nested) == id(deep))           # False — different outer lists
print(id(nested[0]) == id(deep[0]))     # False — different inner lists ✓

deep[0].append(99)
print(nested[0])   # [1, 2] — completely unaffected ✓
print(deep[0])     # [1, 2, 99]

# Works on arbitrarily deep nesting
ultra_nested = {"config": {"db": {"host": "localhost", "port": 5432}}}
safe_copy = copy.deepcopy(ultra_nested)
safe_copy["config"]["db"]["host"] = "testserver"
print(ultra_nested["config"]["db"]["host"])   # "localhost" — unaffected ✓
```

## Visual Memory Model

Understanding the difference visually makes it stick:

```
Original:    list ──→ [  •  ,  •  ,  •  ]
                        |     |     |
                       [1,2] [3,4] [5,6]   ← inner lists

Alias:       list ──→ SAME object as original (same arrow, same list)

Shallow:     list ──→ [  •  ,  •  ,  •  ]  ← NEW outer list
                        |     |     |
                       [1,2] [3,4] [5,6]   ← SAME inner lists (shared!)

Deep:        list ──→ [  •  ,  •  ,  •  ]  ← NEW outer list
                        |     |     |
                       [1,2] [3,4] [5,6]   ← NEW inner lists (independent!)
```

## Comparing All Three Side by Side

This example demonstrates all three with identical operations so you can see exactly how they differ:

```python
import copy

original = [[1, 2], [3, 4]]

alias   = original
shallow = copy.copy(original)
deep    = copy.deepcopy(original)

# --- Operation 1: append to the outer list ---
alias.append([5, 6])     # modifies original's container (they are the same object)
shallow.append([7, 8])   # modifies shallow's container (different object from original)
deep.append([9, 10])     # modifies deep's container (completely separate)

print(original)   # [[1,2],[3,4],[5,6]] — alias added [5,6] to original
# shallow append and deep append did NOT affect original ✓

# --- Operation 2: modify an inner list ---
alias[0].append(99)
print(original[0])   # [1, 2, 99] — alias shares inner lists with original

shallow[0].append(88)
print(original[0])   # [1, 2, 99, 88] — shallow ALSO shares inner lists! ✗

deep[0].append(77)
print(original[0])   # [1, 2, 99, 88] — deep's modification does NOT affect original ✓
```

## Deep Copy with Custom Objects

`copy.deepcopy()` works on any Python object — including custom class instances, because it uses the pickle protocol or `__deepcopy__` to traverse the object graph:

```python
import copy

class TreeNode:
    def __init__(self, value, children=None):
        self.value = value
        self.children = children or []

    def __repr__(self):
        return f"TreeNode({self.value}, {self.children})"

# Build a tree: root(1) → [node(2), node(3 → [node(4)])]
root = TreeNode(1, [TreeNode(2), TreeNode(3, [TreeNode(4)])])

shallow = copy.copy(root)
deep    = copy.deepcopy(root)

# Modifying a nested node through the original
root.children[0].value = 99

print(shallow.children[0].value)  # 99 — shallow copy shares the nested nodes ✗
print(deep.children[0].value)     # 2  — deep copy has its own tree ✓
```

## Controlling `deepcopy` with `__deepcopy__`

Some objects should not be deep copied — database connections, file handles, thread locks, and other resources that represent external state. You can override `copy.deepcopy()`'s behaviour by defining `__deepcopy__` on your class:

```python
import copy

class ApplicationState:
    def __init__(self, config, db_connection):
        self.config = config             # safe to deep copy
        self.db_connection = db_connection  # should NOT be copied — it's a live resource

    def __deepcopy__(self, memo):
        """memo is a dict of {id(original): copy} used to handle circular references."""
        new_state = ApplicationState.__new__(ApplicationState)
        memo[id(self)] = new_state   # register the copy immediately (handles cycles)

        # Deep copy only the data we want to duplicate
        new_state.config = copy.deepcopy(self.config, memo)

        # Reuse the connection — don't copy it
        new_state.db_connection = self.db_connection

        return new_state
```

`__deepcopy__` receives `memo` — a dictionary mapping `id(original_obj)` to its copy. This is how `deepcopy` handles **circular references** without infinite recursion: before recursing into an object's contents, it registers the new copy in `memo`. If the same object is encountered again during recursion, it returns the already-created copy from `memo` instead of recursing again.

## Performance Comparison

Deep copy is significantly more expensive than shallow copy because it must traverse and recreate the entire object graph:

```python
import copy, timeit

data = list(range(1000))   # flat list

t_shallow = timeit.timeit(lambda: copy.copy(data), number=10_000)
t_deep    = timeit.timeit(lambda: copy.deepcopy(data), number=10_000)

print(f"Shallow: {t_shallow:.3f}s")
print(f"Deep:    {t_deep:.3f}s")
# Deep copy is typically 10–50x slower for nested structures
# For a flat list of integers, it's 3–5x slower

# For deeply nested structures, deep copy can be 100x+ slower
nested = [list(range(100)) for _ in range(100)]
t_s = timeit.timeit(lambda: copy.copy(nested), number=1000)
t_d = timeit.timeit(lambda: copy.deepcopy(nested), number=1000)
print(f"Nested shallow: {t_s:.3f}s vs deep: {t_d:.3f}s")
```

This is why the rule is: **use shallow copy unless you have nested mutables**. Don't reach for `deepcopy` by default — it's a more expensive operation.

## When to Use Each

```
Assignment (=):
  → When you WANT a shared reference (intentional aliasing)
  → Example: cache = results (both names should see the same data)

Shallow copy (.copy(), lst[:], copy.copy()):
  → When the outer container needs to be independent BUT inner objects can be shared
  → Best for: flat lists of numbers/strings, configuration dicts with simple values
  → Fastest option

Deep copy (copy.deepcopy()):
  → When you need COMPLETE independence at all levels
  → Best for: lists of lists, nested dicts, object graphs, test fixtures
  → Most expensive — use only when needed

Custom __deepcopy__:
  → When your object has uncopyable attributes (connections, file handles, locks)
  → Selectively deep copy the data and reuse the resources
```

## Interview Questions

**Q: What is the difference between shallow copy and deep copy?**
A shallow copy creates a new outer container but its elements still reference the same objects. Modifying a nested mutable object (like a list inside a list) affects both the original and the copy. A deep copy recursively duplicates everything — every nested object gets a new independent copy. The result is fully independent. Use shallow for flat structures; deep for nested ones.

**Q: What are the different ways to shallow copy a list?**
`lst.copy()`, `lst[:]`, `list(lst)`, and `copy.copy(lst)` are all equivalent shallow copies. For dicts: `d.copy()`, `dict(d)`, and `{**d}`. All create a new outer container but share the inner objects.

**Q: When would `copy.copy()` give the wrong result?**
When the object contains nested mutable objects — a list of lists, a dict containing lists, etc. The outer container is new but the inner objects are shared. Modifying a nested object in the copy also modifies the original. Use `copy.deepcopy()` for nested structures.

**Q: Is `a = b` a copy?**
No. `a = b` makes `a` an alias for the exact same object as `b`. They reference the same memory. Any mutation through either name (`a.append(4)` or `b.append(4)`) modifies the shared object. Only explicit copy operations create new objects.

**Q: Can you always use `deepcopy`?**
Not always. Objects that represent external resources — file handles, database connections, sockets, threading locks — cannot be meaningfully deep copied. `copy.deepcopy()` will raise an error for these unless you define `__deepcopy__` to handle them. The correct approach is to define `__deepcopy__` that copies the data and reuses (or reinitializes) the resource.

**Q: What is the `memo` argument in `__deepcopy__`?**
`memo` is a dictionary mapping `id(original_object)` to its already-created deep copy. `deepcopy` uses it to handle circular references: before recursing into an object, it registers the copy in `memo`. If the same object is encountered again during recursion, it returns the cached copy from `memo` instead of recursing again — preventing infinite loops on circular reference structures.

## Summary

- `a = b` on mutable types → **alias**; both names share the same object; mutations affect both
- **Shallow copy** — new outer container, shared inner objects
  - `lst.copy()`, `lst[:]`, `list(lst)`, `copy.copy(lst)` are all equivalent
  - Fast; correct for flat structures; dangerous for nested mutables
- **Deep copy** — new container AND new copies of all nested objects; fully independent
  - `copy.deepcopy(obj)` — works on any Python object
  - 10–100x slower than shallow copy; use only when true independence is needed
- Nested mutable objects are the key trap — shallow copy is NOT safe for `[[1,2],[3,4]]`
- Custom `__deepcopy__(self, memo)` — control exactly what gets copied; skip uncopyable resources
- `memo` parameter — prevents infinite recursion on circular references by caching created copies
- **Rule of thumb**: default to shallow copy; reach for deep copy when you need nested independence

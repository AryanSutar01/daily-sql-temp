## What Pandas Solves

In data analysis and engineering, you almost never work with raw arrays of numbers. Real-world data is *tabular* — it has labeled columns (name, age, salary, department), a mix of data types (strings, integers, floats, dates), missing values, and meaning attached to row identifiers.

NumPy arrays don't have column names, don't understand mixed types naturally, and don't provide SQL-like operations. **Pandas** was built specifically for this use case. It wraps NumPy arrays in a labeled, axis-aware structure that makes data manipulation intuitive.

The two pandas data structures map directly to database concepts:
- **Series** → a single labeled column (like a SQL result with one column)
- **DataFrame** → a complete table with labeled rows and columns (like a SQL table)

```python
import pandas as pd
import numpy as np
```

## Series — A Labeled 1D Array

A Series is a one-dimensional array where every element has a **label** (the index). Unlike a plain list, you can access elements by label rather than just position. Under the hood, a Series is built on a NumPy array — it gets NumPy's speed while adding indexing and metadata.

```python
# Create from a list — default integer index
s = pd.Series([10, 20, 30, 40, 50])
print(s)
# 0    10
# 1    20
# 2    30
# 3    40
# 4    50
# dtype: int64

# Custom index — the power of Series
s = pd.Series([10, 20, 30], index=["a", "b", "c"])
print(s["b"])   # 20 — label-based access

# From a dict — keys become the index
s = pd.Series({"Alice": 95, "Bob": 82, "Carol": 91})
print(s.index)    # Index(['Alice', 'Bob', 'Carol'])
print(s.values)   # array([95, 82, 91]) — the underlying NumPy array
```

### Series Operations

Series operations are vectorized — they apply to the whole Series at once, aligned on the index.

```python
s = pd.Series([10, 20, 30, 40, 50])

s + 5           # [15, 25, 35, 45, 55] — scalar broadcast
s * 2           # [20, 40, 60, 80, 100]
s[s > 25]       # [30, 40, 50] — boolean filter

s.mean()        # 30.0
s.sum()         # 150
s.max()         # 50
s.min()         # 10
s.std()         # standard deviation
s.describe()    # count, mean, std, min, 25%, 50%, 75%, max — all at once
```

**Index alignment**: When you add two Series with different indices, pandas aligns by index label. If a label exists in one but not the other, the result is `NaN`. This automatic alignment is one of the most powerful features of pandas — it prevents off-by-one errors common when adding NumPy arrays that represent different datasets.

## DataFrame — A Complete Labeled Table

A DataFrame is a 2D table where every column is a Series sharing the same index. You can think of it as an ordered dictionary of Series. Internally, pandas stores each column as a separate NumPy array — this is why column operations are fast (they operate on a single array) while row operations can be slower (they must access multiple arrays).

```python
# From a dict of lists — the most common way to create a DataFrame
df = pd.DataFrame({
    "name": ["Alice", "Bob", "Carol", "Dave"],
    "age": [25, 30, 35, 28],
    "salary": [70000, 85000, 92000, 78000],
    "department": ["Engineering", "Marketing", "Engineering", "HR"],
})

print(df)
#     name  age  salary   department
# 0  Alice   25   70000  Engineering
# 1    Bob   30   85000    Marketing
# 2  Carol   35   92000  Engineering
# 3   Dave   28   78000           HR
```

### Basic DataFrame Attributes

```python
df.shape        # (4, 4) — (rows, columns)
df.dtypes       # data type of each column
df.columns      # Index(['name', 'age', 'salary', 'department'])
df.index        # RangeIndex(start=0, stop=4, step=1)
df.info()       # column names, non-null counts, dtypes, memory usage
df.describe()   # statistics for numeric columns (mean, std, min, quartiles, max)
df.head(2)      # first 2 rows (default 5)
df.tail(2)      # last 2 rows
```

`df.info()` is your first diagnostic tool — it shows how many non-null values each column has. Any column with fewer non-null values than the total row count has missing data.

## Selecting Data

Pandas has two primary selection methods: `loc` (label-based) and `iloc` (position-based). Understanding the difference is essential — they behave differently after filtering, sorting, and reindexing.

```python
# Select a column — returns a Series
df["name"]
df.name         # dot notation (only safe if column name has no spaces/special chars)

# Select multiple columns — returns a DataFrame
df[["name", "salary"]]

# iloc — integer position (always 0-based, like a Python list)
df.iloc[0]         # first row as Series
df.iloc[0:2]       # first 2 rows (exclusive end)
df.iloc[0:2, 1:3]  # rows 0-1, columns at positions 1 and 2

# loc — label-based (INCLUSIVE end for row slices)
df.loc[0]          # row with index label 0
df.loc[0:2]        # rows 0 through 2 — NOTE: this is INCLUSIVE of 2 (unlike iloc)
df.loc[0:2, ["name", "salary"]]  # rows 0-2, specific columns by name
```

**The critical difference**: with a default integer index, `loc[0:2]` gives 3 rows (0, 1, 2) while `iloc[0:2]` gives 2 rows (0, 1). After filtering or setting a custom index, `loc` uses the actual label values while `iloc` uses the position in the result.

## Filtering Rows

Row filtering uses **boolean indexing** — create a boolean Series, then use it to select rows.

```python
# Boolean filter — most common approach
df[df["age"] > 28]
df[df["department"] == "Engineering"]

# Multiple conditions — always use & (AND) and | (OR), not Python's 'and'/'or'
df[(df["age"] > 25) & (df["salary"] > 80000)]    # AND
df[(df["department"] == "Engineering") | (df["department"] == "HR")]   # OR

# isin — match any value in a list (cleaner than multiple OR conditions)
df[df["department"].isin(["Engineering", "Marketing"])]

# query method — SQL-like string syntax (easier to read for complex conditions)
df.query("age > 28 and salary > 80000")
df.query("department in ['Engineering', 'HR']")
```

**Why not use Python's `and`?** `df["age"] > 25 and df["salary"] > 80000` raises `ValueError` because `and` tries to evaluate the truthiness of the whole Series (ambiguous). Use `&` for element-wise AND and `|` for element-wise OR. Always wrap each condition in parentheses.

## Adding & Modifying Columns

Pandas DataFrames are mutable — you can add, modify, and drop columns in place.

```python
# Add new column
df["bonus"] = df["salary"] * 0.1
df["senior"] = df["age"] >= 30   # boolean column

# Conditional column with np.where
import numpy as np
df["level"] = np.where(df["salary"] > 80000, "Senior", "Junior")

# Apply a function to a column — for simple element-wise transforms
df["name_upper"] = df["name"].str.upper()
df["salary_lakhs"] = df["salary"].apply(lambda x: x / 100000)

# Rename columns
df.rename(columns={"name": "full_name", "age": "age_years"}, inplace=True)

# Drop columns
df.drop(columns=["bonus", "senior"], inplace=True)
```

**`inplace=True`**: Most pandas operations return a new DataFrame by default. `inplace=True` modifies the original. However, many experienced developers prefer to avoid `inplace=True` and use reassignment (`df = df.drop(...)`) for clarity — it makes the code easier to chain and debug.

## Sorting

```python
df.sort_values("salary", ascending=False)
df.sort_values(["department", "salary"], ascending=[True, False])   # sort by multiple columns
df.sort_values("salary").reset_index(drop=True)   # reset index to 0,1,2... after sort
```

## Reading & Writing Data

Pandas can read from and write to virtually any data format used in modern data pipelines.

```python
# Read
df = pd.read_csv("data.csv")
df = pd.read_csv("data.csv", sep=";", encoding="utf-8")
df = pd.read_csv("data.csv", parse_dates=["date_column"])
df = pd.read_csv("data.csv", usecols=["name", "salary"])  # only specific columns
df = pd.read_csv("data.csv", nrows=1000)                  # only first 1000 rows

df = pd.read_excel("data.xlsx", sheet_name="Sheet1")
df = pd.read_json("data.json")

# Parquet — columnar format, excellent for analytics (stores column dtypes)
df = pd.read_parquet("data.parquet")

# From a database
import sqlalchemy
engine = sqlalchemy.create_engine("postgresql://user:pass@host/db")
df = pd.read_sql("SELECT * FROM orders", engine)
df = pd.read_sql("SELECT * FROM orders WHERE status = %(status)s", engine,
                  params={"status": "completed"})

# Write
df.to_csv("output.csv", index=False)         # index=False prevents writing the index as a column
df.to_excel("output.xlsx", index=False)
df.to_parquet("output.parquet", index=False)
df.to_json("output.json", orient="records")
df.to_sql("table_name", engine, if_exists="append", index=False)
```

**Parquet vs CSV**: CSV is human-readable but stores everything as text (you lose type information). Parquet is a columnar binary format that preserves dtypes, compresses well, and is dramatically faster to read for large datasets. Use parquet for production data pipelines.

## Handling Missing Data

Missing data (`NaN` — Not a Number) is inevitable in real-world datasets. Pandas represents missing numeric data as `NaN` (a special float value) and missing non-numeric data as `None` or `pd.NaT` (for datetime).

```python
df = pd.DataFrame({
    "name": ["Alice", "Bob", None, "Dave"],
    "age": [25, None, 35, 28],
    "salary": [70000, 85000, 92000, None],
})

# Detection
df.isnull()             # boolean mask of NaN locations
df.isnull().sum()       # count NaN per column — your first data quality check
df.isnull().mean() * 100  # percentage missing per column

# Dropping — removes data; appropriate when missing values are few and random
df.dropna()                     # drop any row with at least one NaN
df.dropna(subset=["age"])       # drop rows where age is NaN
df.dropna(thresh=3)             # keep rows with at least 3 non-NaN values

# Filling — imputation; appropriate when you want to preserve rows
df.fillna(0)                    # fill all NaN with 0
df["age"].fillna(df["age"].mean(), inplace=True)     # fill with column mean
df["salary"].fillna(df["salary"].median(), inplace=True)  # median is more robust to outliers
df["name"].fillna("Unknown", inplace=True)
```

**When to drop vs fill**: Drop when the proportion of missing values is small (< 5%) and the data is missing completely at random. Fill (impute) when you want to preserve rows — use mean/median for numeric columns and the mode or a constant for categorical columns.

## String Operations

Pandas provides vectorized string methods via the `.str` accessor — these work on the entire column without a Python loop.

```python
df["name"].str.upper()
df["name"].str.lower()
df["name"].str.strip()                     # remove leading/trailing whitespace
df["name"].str.contains("Ali")            # boolean: does it contain this substring?
df["name"].str.startswith("A")
df["name"].str.replace("Alice", "Alicia")
df["name"].str.split(" ", expand=True)    # split into multiple columns
df["name"].str.len()                      # length of each string
df["email"].str.extract(r"@(.+)")         # extract regex group into new column
```

## Interview Questions

**Q: What is the difference between `loc` and `iloc`?**
`loc` selects by **label** — it uses the actual index values and column names. `iloc` selects by **integer position** — it always uses 0-based positions regardless of the index. With a default integer index they look the same, but they diverge when you filter rows (which changes positions but not labels) or when you have a custom string index. `loc[0:2]` gives 3 rows (labels 0, 1, 2 — inclusive); `iloc[0:2]` gives 2 rows (positions 0, 1 — exclusive end).

**Q: What is the difference between a Series and a DataFrame?**
A Series is one-dimensional — a single column with an index. A DataFrame is two-dimensional — a table of multiple columns, where each column is a Series sharing the same index. Internally, a DataFrame is an ordered collection of Series stored as NumPy arrays per column.

**Q: How do you select rows where multiple conditions are true?**
Use `&` (AND) or `|` (OR) with boolean masks, wrapping each condition in parentheses: `df[(df["age"] > 25) & (df["salary"] > 80000)]`. You cannot use Python's `and`/`or` because they evaluate the truthiness of the whole Series (which is ambiguous). Alternatively, use `df.query("age > 25 and salary > 80000")` for cleaner syntax.

**Q: What is `inplace=True` in pandas?**
By default, most pandas operations return a **new** DataFrame without modifying the original. `inplace=True` modifies the original in place and returns `None`. However, using `inplace=True` can prevent method chaining and makes the code harder to read. Many teams prefer explicit reassignment: `df = df.sort_values("salary")`.

**Q: How do you handle missing values in pandas?**
First understand why data is missing and how much: `df.isnull().sum()`. Then decide: **drop** rows with `dropna()` when the amount of missing data is small and data is missing at random; **fill** with `fillna()` when you want to preserve rows. For numeric columns, filling with the mean or median is common. For categorical columns, use the mode or a placeholder like `"Unknown"`. For time series, use forward fill (`ffill`) to propagate the last known value.

**Q: When should you use parquet instead of CSV?**
For any dataset larger than a few MB in production. Parquet preserves column dtypes (no need to re-parse dates and numbers on load), compresses far better than CSV, and can be read in a fraction of the time. CSV is only preferred when human readability is essential or when sharing data with non-technical stakeholders.

## Summary

- **Series** — 1D labeled array; each element has an index label; built on NumPy
- **DataFrame** — 2D table; each column is a Series sharing the same index; stored as one NumPy array per column
- `iloc` — integer position (0-based, like Python list); `loc` — label-based (inclusive end)
- Boolean filtering: `df[df["col"] > value]`; multiple conditions: `(cond1) & (cond2)` with `&`/`|`
- `df.query()` — SQL-like string filter syntax for complex conditions
- `isnull().sum()` — count missing values; `dropna()` to remove; `fillna()` to impute
- `.str.upper()`, `.str.contains()`, `.str.split()` — vectorized string operations
- `read_csv()`, `read_parquet()`, `read_sql()` — ingest data from many sources
- `to_csv()`, `to_parquet()`, `to_sql()` — write data to file or database
- Use `index=False` when writing to CSV/Excel to avoid writing the RangeIndex as a column

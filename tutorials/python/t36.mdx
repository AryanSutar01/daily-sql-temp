## Two Approaches

```
Raw drivers (psycopg2, mysql-connector)
  → Direct SQL execution
  → Full control, less abstraction
  → Best for data engineering, ETL, analytics

SQLAlchemy
  → Two modes: Core (SQL expression language) and ORM (Python classes = tables)
  → More abstraction, database-agnostic
  → Best for web apps, complex data models
```

## psycopg2 - Raw PostgreSQL Driver

```bash

```

```python
import psycopg2

# Connect
conn = psycopg2.connect(
    host="localhost",
    port=5432,
    database="mydb",
    user="postgres",
    password="secret",
)

cursor = conn.cursor()

# Execute a query
cursor.execute("SELECT id, name, salary FROM employees WHERE salary > %s", (80000,))
rows = cursor.fetchall()   # list of tuples

for row in rows:
    print(row)   # (1, 'Alice', 90000)

# Fetch one row
cursor.execute("SELECT * FROM employees WHERE id = %s", (1,))
row = cursor.fetchone()

# Close
cursor.close()
conn.close()
```

## Always Use Context Managers

```python
import psycopg2
from contextlib import contextmanager

@contextmanager
def get_connection():
    conn = psycopg2.connect(
        host="localhost", database="mydb",
        user="postgres", password="secret",
    )
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
    finally:
        conn.close()

# Usage
with get_connection() as conn:
    with conn.cursor() as cur:
        cur.execute("SELECT * FROM employees")
        rows = cur.fetchall()
```

## INSERT, UPDATE, DELETE

```python
with get_connection() as conn:
    with conn.cursor() as cur:
        # INSERT
        cur.execute(
            "INSERT INTO employees (name, salary, department) VALUES (%s, %s, %s)",
            ("Alice", 90000, "Engineering"),
        )

        # INSERT many rows efficiently
        data = [("Bob", 75000, "Marketing"), ("Carol", 85000, "Engineering")]
        cur.executemany(
            "INSERT INTO employees (name, salary, department) VALUES (%s, %s, %s)",
            data,
        )

        # UPDATE
        cur.execute(
            "UPDATE employees SET salary = %s WHERE id = %s",
            (95000, 1),
        )

        # DELETE
        cur.execute("DELETE FROM employees WHERE id = %s", (5,))
```

## Fetch Results as Dicts

```python
import psycopg2.extras

with psycopg2.connect(...) as conn:
    with conn.cursor(cursor_factory=psycopg2.extras.RealDictCursor) as cur:
        cur.execute("SELECT id, name, salary FROM employees")
        rows = cur.fetchall()

for row in rows:
    print(row["name"], row["salary"])   # dict access instead of tuple index
```

## SQLAlchemy - Core

```bash
pip install sqlalchemy psycopg2-binary
```

```python
from sqlalchemy import create_engine, text

# Connection string format: dialect+driver://user:password@host:port/database
engine = create_engine(
    "postgresql+psycopg2://postgres:secret@localhost:5432/mydb",
    echo=False,      # True to log all SQL
    pool_size=5,     # connection pool size
    pool_timeout=30,
)

# Execute raw SQL
with engine.connect() as conn:
    result = conn.execute(text("SELECT id, name, salary FROM employees WHERE salary > :min_salary"),
                          {"min_salary": 80000})
    for row in result:
        print(row.name, row.salary)
```

## SQLAlchemy - pandas Integration

```python
import pandas as pd
from sqlalchemy import create_engine

engine = create_engine("postgresql+psycopg2://postgres:secret@localhost:5432/mydb")

# Read
df = pd.read_sql("SELECT * FROM orders WHERE status = 'completed'", engine)

# Read with params
df = pd.read_sql(
    "SELECT * FROM orders WHERE created_at >= %(start_date)s",
    engine,
    params={"start_date": "2024-01-01"},
)

# Write
df.to_sql("processed_orders", engine, if_exists="append", index=False)
df.to_sql("staging_table", engine, if_exists="replace", index=False, chunksize=1000)
```

## SQLAlchemy ORM

```python
from sqlalchemy import Column, Integer, String, Float, create_engine
from sqlalchemy.orm import DeclarativeBase, Session

class Base(DeclarativeBase):
    pass

class Employee(Base):
    __tablename__ = "employees"

    id = Column(Integer, primary_key=True)
    name = Column(String(100), nullable=False)
    salary = Column(Float)
    department = Column(String(100))

    def __repr__(self):
        return f"Employee(id={self.id}, name={self.name}, salary={self.salary})"

engine = create_engine("postgresql+psycopg2://postgres:secret@localhost:5432/mydb")
Base.metadata.create_all(engine)   # create tables if not exist

# CRUD Operations
with Session(engine) as session:
    # Create
    emp = Employee(name="Alice", salary=90000, department="Engineering")
    session.add(emp)
    session.commit()

    # Read
    employees = session.query(Employee).filter(Employee.salary > 80000).all()
    for e in employees:
        print(e)

    # Update
    emp = session.query(Employee).filter_by(name="Alice").first()
    emp.salary = 95000
    session.commit()

    # Delete
    session.query(Employee).filter_by(name="Alice").delete()
    session.commit()
```

## Connection Pooling

```python
from sqlalchemy import create_engine
from sqlalchemy.pool import QueuePool

engine = create_engine(
    "postgresql+psycopg2://postgres:secret@localhost:5432/mydb",
    poolclass=QueuePool,
    pool_size=10,          # number of persistent connections
    max_overflow=20,       # extra connections allowed under load
    pool_timeout=30,       # seconds to wait for a connection
    pool_recycle=3600,     # recycle connections after 1 hour (avoid stale connections)
)
```

## Interview Questions

**Q: What is the difference between psycopg2 and SQLAlchemy?**
psycopg2 is a low-level PostgreSQL driver - you write raw SQL strings and it executes them. SQLAlchemy is a higher-level toolkit with two modes: Core (SQL expression builder) and ORM (map Python classes to tables). psycopg2 gives full control; SQLAlchemy adds abstraction, database portability, and ORM features.

**Q: Why should you use parameterized queries instead of string formatting?**
String formatting is vulnerable to SQL injection - a user can pass malicious input that changes the query. Parameterized queries (`%s` or `:param`) pass values separately from SQL, so the driver safely escapes them. Never use f-strings or `%` formatting to build SQL queries.

**Q: What is connection pooling and why is it important?**
Opening a new database connection for every query is expensive - it involves TCP handshake, authentication, and memory allocation. A connection pool maintains a set of pre-opened connections that are reused across requests. SQLAlchemy's engine has a built-in pool, which is why you create one engine per application, not one per request.

**Q: What does `if_exists="replace"` vs `"append"` do in `to_sql()`?**
`"replace"` drops and recreates the table before inserting. `"append"` adds rows to an existing table. `"fail"` (default) raises an error if the table already exists. Use `"append"` for incremental loads and `"replace"` for full refreshes.

**Q: What is the SQLAlchemy ORM and when would you use it over raw SQL?**
The ORM maps Python classes to database tables - you work with Python objects instead of SQL strings. Use the ORM in web applications where you model business entities. Use raw SQL or SQLAlchemy Core for analytics, ETL, or performance-critical bulk operations where you need full SQL control.

## Summary

- **psycopg2** - low-level PostgreSQL driver; write raw SQL; always use parameterized queries (`%s`)
- Use context managers for connections - ensures commit/rollback and cleanup
- `executemany()` - bulk insert multiple rows efficiently
- `RealDictCursor` - returns rows as dicts instead of tuples
- **SQLAlchemy Core** - SQL expression builder; database-agnostic; works with `pd.read_sql()` and `df.to_sql()`
- **SQLAlchemy ORM** - map Python classes to tables; full CRUD with Python objects
- Connection pool - reuse connections; set `pool_size`, `max_overflow`, `pool_recycle`
- Never hardcode credentials - use environment variables with `python-dotenv`

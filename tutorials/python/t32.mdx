## Why Data Cleaning Is the Majority of Real-World Data Work

A common misconception in data science is that the analysis and modeling are the primary tasks. In practice, data engineers and analysts spend **60–80% of their time cleaning and transforming data** before it is ready for any analysis. Raw data from production systems, CSV exports, web scraping, or external APIs is almost never clean.

Understanding *why* data is dirty is as important as knowing how to fix it:
- **Missing values**: sensors fail, forms have optional fields, ETL jobs skip rows on errors
- **Wrong data types**: everything in a CSV file is a string — dates, numbers, booleans all need parsing
- **Duplicates**: event-based systems can log the same event twice; joins can produce duplicate rows
- **Inconsistent formatting**: "Engineering", "engineering", " Engineering " are three different values
- **Outliers**: data entry errors (age = 999), sensor malfunctions, or genuinely extreme values

A systematic data cleaning workflow transforms raw, unreliable data into a trustworthy dataset your analysis can depend on.

## Diagnosing the Data

Before writing any cleaning code, you need to understand what you have. The `info()` and `describe()` methods are your primary diagnostic tools.

```python
df.info()
# Columns, dtypes, non-null counts, memory usage
# Any column with fewer non-null values than the row count has missing data

df.describe()
# For numeric columns: count, mean, std, min, 25%, 50%, 75%, max
# Check for impossible values (min age = -5, max salary = 99999999)
# Check for suspicious distributions (mean ≠ median → likely outliers or skew)

# Check categorical columns
df["department"].value_counts()
# Reveals inconsistent categories: "Engineering", "engineering", "Eng", " Engineering"

df["department"].value_counts(normalize=True)   # as proportions

# Profile missing data across columns
df.isnull().sum() / len(df) * 100   # percentage missing per column
```

## Fixing Data Types

When you read data from a CSV file, every column comes in as a string (`object` dtype in pandas). Incorrect dtypes prevent numerical operations, incorrect sorting, and incorrect aggregations.

```python
# Inspect current dtypes
df.dtypes

# Convert numeric columns
df["salary"] = pd.to_numeric(df["salary"], errors="coerce")
# errors="coerce" converts non-numeric values to NaN instead of raising an error
# errors="raise" (default) throws ValueError on bad values
# errors="ignore" silently keeps bad values as-is (usually wrong choice)

# Convert date columns
df["join_date"] = pd.to_datetime(df["join_date"], format="%Y-%m-%d")
df["join_date"] = pd.to_datetime(df["join_date"], errors="coerce")   # NaT for bad dates

# Convert to categorical (saves memory for low-cardinality string columns)
df["department"] = df["department"].astype("category")
# Categorical dtypes store unique values once — major memory savings for repetitive strings

# Convert boolean
df["is_active"] = df["is_active"].astype(bool)
df["is_active"] = df["is_active"].map({"True": True, "False": False, "1": True, "0": False})
```

**Why `errors="coerce"` matters**: If a salary column has one value like "N/A" or "confidential" in 10,000 rows, `pd.to_numeric(col)` will throw an error and your entire pipeline fails. `errors="coerce"` converts those problematic values to `NaN`, letting you proceed and handle the missing values separately.

## Handling Missing Values

Missing value strategy depends on the nature of the data and how much is missing. There is no universal answer — you need to reason about the data.

```python
# Detection
df.isnull().sum()              # count per column
df.isnull().mean() * 100       # percentage per column
df.isnull().any(axis=1)        # boolean: does each row have at least one NaN?

# Drop rows — when missing data is random and small proportion
df.dropna()                    # drop rows with ANY NaN
df.dropna(subset=["salary"])   # drop only rows where salary is NaN
df.dropna(thresh=3)            # keep rows with at least 3 non-null values

# Drop columns with too much missing data
threshold = 0.5   # drop columns with > 50% missing
df.dropna(axis=1, thresh=int(len(df) * (1 - threshold)))

# Fill with scalar
df["status"].fillna("Unknown", inplace=True)
df["rating"].fillna(0, inplace=True)

# Fill with column statistics (imputation)
df["age"].fillna(df["age"].mean(), inplace=True)       # mean (sensitive to outliers)
df["salary"].fillna(df["salary"].median(), inplace=True)  # median (robust to outliers)
df["department"].fillna(df["department"].mode()[0], inplace=True)  # most frequent value

# Fill with group-specific statistic (better imputation for grouped data)
df["salary"] = df.groupby("department")["salary"].transform(
    lambda x: x.fillna(x.median())
)
# Fills each missing salary with the median salary for that employee's department
# Better than the overall median — accounts for pay differences across departments

# Forward fill / backward fill (time series)
df["temperature"].fillna(method="ffill")   # use last known value
df["temperature"].fillna(method="bfill")   # use next known value
df["temperature"].interpolate()             # linear interpolation
```

**Group-based imputation** is a significant improvement over simple mean/median imputation. An engineer's salary is better estimated from engineering salaries, not from the company-wide average that includes executives and interns.

## Removing Duplicates

Duplicates inflate counts, skew aggregations, and corrupt join results. In production data pipelines, duplicates are one of the most common data quality issues.

```python
# Detect
df.duplicated().sum()          # how many exact duplicate rows?
df.duplicated(subset=["employee_id"]).sum()   # duplicates based on a key column

# Inspect a sample of duplicates
df[df.duplicated(keep=False)]  # show ALL rows that have duplicates (not just the second)

# Remove
df.drop_duplicates(inplace=True)
df.drop_duplicates(subset=["employee_id"])   # keep first occurrence of each ID
df.drop_duplicates(subset=["employee_id"], keep="last")   # keep the most recent row
```

**Why `keep=False`**: `keep=False` marks *all* copies of a duplicate as True in the boolean mask, so you can inspect every duplicate row. The default `keep="first"` marks only second-and-beyond occurrences. Use `keep=False` to diagnose; use `keep="first"` or `keep="last"` to deduplicate.

## Standardizing Text

String inconsistency is a silent killer in data pipelines. "Engineering" and "engineering" appear as two completely different groups in a groupby, producing wrong counts and wrong aggregations.

```python
# Standardize case
df["department"] = df["department"].str.strip()   # always do this first
df["department"] = df["department"].str.lower()
# or
df["department"] = df["department"].str.title()   # Title Case Each Word

# Fix specific values using a mapping
dept_map = {
    "eng": "Engineering",
    "engineering": "Engineering",
    "Eng": "Engineering",
    "mktg": "Marketing",
    "marketing": "Marketing",
}
df["department"] = df["department"].str.lower().map(dept_map).fillna(df["department"])

# Replace patterns with regex
df["phone"] = df["phone"].str.replace(r"[^\d]", "", regex=True)  # keep only digits

# Standardize email format
df["email"] = df["email"].str.strip().str.lower()

# Remove unwanted characters
df["name"] = df["name"].str.replace(r"[^a-zA-Z\s]", "", regex=True)
```

## Detecting and Handling Outliers

Outliers are values that lie far from the typical range. They can be genuine extreme values (a CEO's salary in an employee dataset), data entry errors (age = 999), or measurement errors (negative temperatures in a dataset of body temperatures).

```python
# Method 1: IQR (Interquartile Range) — most robust statistical method
Q1 = df["salary"].quantile(0.25)
Q3 = df["salary"].quantile(0.75)
IQR = Q3 - Q1
lower = Q1 - 1.5 * IQR
upper = Q3 + 1.5 * IQR

outliers = df[(df["salary"] < lower) | (df["salary"] > upper)]
print(f"Found {len(outliers)} outliers")

# Remove outliers
df_clean = df[(df["salary"] >= lower) & (df["salary"] <= upper)]

# Clip outliers (cap at boundary instead of removing)
df["salary"] = df["salary"].clip(lower=lower, upper=upper)

# Method 2: Z-score — assumes normal distribution
from scipy import stats
z_scores = np.abs(stats.zscore(df["salary"].dropna()))
df_clean = df[z_scores < 3]   # keep values within 3 standard deviations

# Method 3: Visual inspection (always do this for numeric columns)
import matplotlib.pyplot as plt
df["salary"].hist(bins=50)
df.boxplot(column="salary", by="department")
```

**IQR vs Z-score**: The IQR method is robust — it doesn't assume a normal distribution and isn't distorted by the outliers themselves. Z-score assumes the data is roughly normally distributed and uses the mean and std, which are themselves influenced by outliers. For most real-world datasets, IQR is the safer choice.

## Feature Engineering

Feature engineering creates new columns from existing ones to expose patterns useful for analysis or modeling. It's where domain knowledge meets data manipulation.

```python
# Extract components from dates
df["year"] = df["join_date"].dt.year
df["month"] = df["join_date"].dt.month
df["day_of_week"] = df["join_date"].dt.day_name()   # Monday, Tuesday...
df["quarter"] = df["join_date"].dt.quarter
df["tenure_days"] = (pd.Timestamp.now() - df["join_date"]).dt.days

# Bin continuous values into categories
df["age_group"] = pd.cut(df["age"],
                         bins=[0, 25, 35, 45, 100],
                         labels=["<25", "25-35", "35-45", "45+"])
df["salary_tier"] = pd.qcut(df["salary"], q=4, labels=["Q1", "Q2", "Q3", "Q4"])
# pd.cut — equal-width bins; pd.qcut — equal-frequency bins (same number of rows in each)

# Interaction features
df["salary_per_year_experience"] = df["salary"] / df["years_experience"]

# Encode categoricals for ML
dummies = pd.get_dummies(df["department"], prefix="dept", drop_first=True)
df = pd.concat([df, dummies], axis=1)
```

## Building a Reusable Cleaning Pipeline

In production, data cleaning logic should be encapsulated in reusable functions so the same transformations apply consistently to training data, validation data, and production data.

```python
def clean_employee_data(df: pd.DataFrame) -> pd.DataFrame:
    """Clean and standardize the employee dataset.
    
    This function is idempotent — running it twice produces the same result.
    """
    df = df.copy()   # never modify the input; return a new DataFrame
    
    # 1. Fix types
    df["salary"] = pd.to_numeric(df["salary"], errors="coerce")
    df["join_date"] = pd.to_datetime(df["join_date"], errors="coerce")
    
    # 2. Remove duplicates
    df.drop_duplicates(subset=["employee_id"], keep="last", inplace=True)
    
    # 3. Standardize text
    df["department"] = df["department"].str.strip().str.title()
    df["email"] = df["email"].str.strip().str.lower()
    
    # 4. Handle missing values
    df["salary"].fillna(df.groupby("department")["salary"].transform("median"), inplace=True)
    df["department"].fillna("Unknown", inplace=True)
    
    # 5. Feature engineering
    df["tenure_days"] = (pd.Timestamp.now() - df["join_date"]).dt.days
    
    return df

# Apply to data
clean_df = clean_employee_data(raw_df)
```

**Idempotency** is a critical property for data pipelines: running the same cleaning function multiple times on the same data should always produce the same result. Starting with `df = df.copy()` ensures the function doesn't have side effects on the caller's data.

## Interview Questions

**Q: What is the difference between `errors="coerce"`, `errors="raise"`, and `errors="ignore"` in `pd.to_numeric()`?**
`errors="raise"` (default) throws an exception on any non-numeric value — the entire conversion fails. `errors="coerce"` silently converts non-numeric values to `NaN`, letting you handle them later with `fillna()` or `dropna()`. `errors="ignore"` returns the original data unchanged when it can't convert. In production pipelines, `errors="coerce"` is the right choice because it gives you control — you can then quantify and handle the bad values rather than crashing.

**Q: What is the difference between `pd.cut` and `pd.qcut`?**
`pd.cut` creates bins of **equal width** — the range of values is divided into equally-sized intervals. `pd.qcut` creates bins with **equal frequency** — each bin contains approximately the same number of rows. Use `pd.cut` when the bin boundaries have business meaning (e.g., age 0-18, 18-65, 65+). Use `pd.qcut` for quartiles or when you want each group to have roughly the same size.

**Q: How would you fill missing salaries in a way that accounts for department differences?**
Use group-specific imputation via `groupby` and `transform`:
```python
df["salary"] = df.groupby("department")["salary"].transform(
    lambda x: x.fillna(x.median())
)
```
This fills each missing salary with the median salary for that employee's department, rather than the overall median. It's a much better estimate because salary distributions vary significantly across departments.

**Q: Why should data cleaning functions be idempotent?**
In data pipelines, the same cleaning step may be applied multiple times — for example, when retrying a failed job or applying the function to both training and test data. An idempotent function always produces the same output from the same input, regardless of how many times it's called. This prevents bugs like duplicating rows or applying string transformations multiple times. Starting with `df = df.copy()` ensures no side effects.

**Q: When should you remove outliers vs clip them?**
**Remove** when the outlier is clearly erroneous data (age = 999, negative price) and you have enough remaining data. **Clip** (cap at a threshold using `.clip()`) when the outlier might be a real but extreme value — for example, capping salaries at the 99th percentile preserves the information that some salaries are very high without letting extreme values distort statistics. Clipping is preferred in ML pipelines because it preserves row count.

## Summary

- Always diagnose first: `df.info()`, `df.describe()`, `df.isnull().sum()`, `df.duplicated().sum()`
- `pd.to_numeric(col, errors="coerce")` — convert to numbers, make bad values NaN
- `pd.to_datetime(col, errors="coerce")` — parse dates, make bad values NaT
- `str.strip().str.lower()` — always strip whitespace before any text comparison
- `fillna(df.groupby("col")["target"].transform("median"))` — group-aware imputation
- `drop_duplicates(subset=["id"], keep="last")` — deduplicate on business key
- IQR method — robust outlier detection; `clip(lower, upper)` to cap instead of remove
- `pd.cut(bins=[...])` — equal-width bins; `pd.qcut(q=4)` — equal-frequency bins
- Encapsulate cleaning in a reusable function; start with `df = df.copy()` for idempotency
- `"category"` dtype — memory-efficient storage for low-cardinality string columns

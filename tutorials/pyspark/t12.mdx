## How groupBy Works Inside Spark

`groupBy()` is one of the most important — and most expensive — operations in Spark. It is a **wide transformation** that requires a shuffle. Understanding the internal mechanism helps you write efficient aggregations and debug performance problems.

### The Two-Stage Aggregation Model

When you call `df.groupBy("dept").agg(sum("salary"))`, Spark does **not** immediately shuffle all rows to group them. Instead it uses a two-stage strategy:

```
Stage 1 — Partial Aggregation (Map-Side):
Each partition independently aggregates its own rows.
No data moves. Each partition produces partial results.

Executor 1, Partition 0:              Executor 2, Partition 1:
  Raw: Engineering:95000              Raw: Engineering:105000
       Marketing:72000                     HR:60000
  Partial: Engineering→95000          Partial: Engineering→105000
           Marketing→72000                    HR→60000

Stage 2 — Shuffle + Final Aggregation (Reduce-Side):
All partial results for the same key are shuffled to the same executor.
Final aggregation merges the partial results.

After shuffle → all "Engineering" rows arrive together:
  Engineering: 95000 + 110000 + 105000 + 90000 = 400000
```

The key insight: **Stage 1 dramatically reduces the data volume before the shuffle**. Instead of shuffling every raw row, Spark shuffles only the pre-aggregated partial sums — often 100x less data.

### Why spark.sql.shuffle.partitions Matters

The number of post-shuffle partitions is controlled by `spark.sql.shuffle.partitions` (default: 200). For small datasets, 200 partitions means 200 tiny tasks — overhead dominates. For huge datasets, 200 partitions might be too few:

```python
# For small/medium data — reduce shuffle partitions
spark.conf.set("spark.sql.shuffle.partitions", "10")

# For very large data — increase
spark.conf.set("spark.sql.shuffle.partitions", "500")

# Spark 3.0+ AQE can adjust this automatically
spark.conf.set("spark.sql.adaptive.enabled", "true")
```

### count("col") vs count("*") — The NULL Trap

`count("column_name")` counts only **non-null** values in that column. `count("*")` or `count(lit(1))` counts **all rows** including those with nulls. This distinction is critical for correct aggregations:

```python
# If salary has 2 null rows in Engineering:
df.groupBy("dept").agg(count("salary"))  # Engineering → 2 (nulls excluded!)
df.groupBy("dept").agg(count("*"))       # Engineering → 4 (all rows)
```

from pyspark.sql import SparkSession

## agg() - Multiple Aggregations at Once

```python
from pyspark.sql.functions import (
    count, sum, avg, min, max, countDistinct,
    stddev, variance, first, last, collect_list, collect_set
)

# Multiple aggregations in one groupBy
df.groupBy("dept").agg(
    count("id").alias("employee_count"),
    sum("salary").alias("total_salary"),
    avg("salary").alias("avg_salary"),
    min("salary").alias("min_salary"),
    max("salary").alias("max_salary"),
).show()

# +--co-----------+---------------+------------+-----------+-----------+-----------+
# |       dept|employee_count|total_salary|avg_salary|min_salary|max_salary|
# +-----------+--------------+------------+----------+----------+----------+
# |Engineering|             4|      400000|  100000.0|     90000|    110000|
# |  Marketing|             2|      150000|   75000.0|     72000|     78000|
# |         HR|             2|      125000|   62500.0|     60000|     65000|
# +-----------+--------------+------------+----------+----------+----------+
```

## All Aggregation Functions

```python
from pyspark.sql.functions import *

df.groupBy("dept").agg(
    # Count
    count("id").alias("row_count"),
    count("*").alias("row_count_all"),          # counts NULLs too
    countDistinct("country").alias("country_count"),

    # Sum / Avg
    sum("salary").alias("total_salary"),
    avg("salary").alias("avg_salary"),
    mean("salary").alias("mean_salary"),         # alias for avg

    # Min / Max
    min("salary").alias("min_salary"),
    max("salary").alias("max_salary"),

    # Statistical
    stddev("salary").alias("stddev_salary"),
    variance("salary").alias("variance_salary"),

    # First / Last (nondeterministic without orderBy)
    first("name").alias("first_name"),
    last("name").alias("last_name"),

    # Collect into arrays
    collect_list("name").alias("all_names"),      # keeps duplicates
    collect_set("country").alias("countries"),    # deduplicates
).show(truncate=False)
```

## Filtering After Aggregation - Having Clause

```python
# SQL equivalent: HAVING count > 1
df.groupBy("dept").agg(
    count("id").alias("cnt"),
    avg("salary").alias("avg_sal")
).filter(col("cnt") > 1).show()   # filter AFTER agg = HAVING

# Chained with ordering
df.groupBy("dept").agg(
    count("*").alias("emp_count"),
    sum("salary").alias("total_salary")
).filter(col("emp_count") >= 2) \
 .orderBy(col("total_salary").desc()) \
 .show()
```

## Filtering Before Aggregation - WHERE Clause

```python
# SQL equivalent: WHERE country = 'US' GROUP BY dept
df.filter(col("country") == "US") \
  .groupBy("dept") \
  .agg(count("id").alias("us_employees")) \
  .show()

# Full WHERE + GROUP BY + HAVING pattern
df \
    .filter(col("salary") > 70000) \          # WHERE
    .groupBy("dept") \                         # GROUP BY
    .agg(count("id").alias("cnt"),             #
         avg("salary").alias("avg_sal")) \     # aggregations
    .filter(col("cnt") >= 2) \                 # HAVING
    .orderBy(col("avg_sal").desc()) \          # ORDER BY
    .show()
```

## Aggregation on All Rows (No groupBy)

```python
# Global aggregation - no GROUP BY
from pyspark.sql.functions import count, sum, avg, max

df.agg(
    count("*").alias("total_employees"),
    sum("salary").alias("total_salary"),
    avg("salary").alias("avg_salary"),
    max("salary").alias("max_salary")
).show()
```

## rollup - Hierarchical Subtotals

```python
# rollup adds subtotal rows for each level of grouping
df.rollup("dept", "country").agg(
    count("id").alias("cnt"),
    sum("salary").alias("total_sal")
).orderBy("dept", "country").show()

# +--co-----------+-------+---+----------+
# |       dept|country|cnt|total_sal|
# +-----------+-------+---+---------+
# |       null|   null| 8 |  675000 |  ← grand total
# |Engineering|   null| 4 |  400000 |  ← dept subtotal
# |Engineering|     GB| 1 |  105000 |
# |Engineering|     IN| 1 |   90000 |
# |Engineering|     US| 2 |  205000 |
# |         HR|   null| 2 |  125000 |  ← dept subtotal
# ...
```

## cube - All Combinations of Subtotals

```python
# cube gives all possible subtotals (more powerful than rollup)
df.cube("dept", "country").agg(
    count("id").alias("cnt")
).orderBy("dept", "country").show()
# Includes: grand total, per-dept, per-country, and per-dept+country
```

## pivot - Reshape GroupBy to Wide Format

```python
# Pivot: dept as rows, country as columns, avg salary as values
df.groupBy("dept").pivot("country").avg("salary").show()
# +-----------+--------+--------+--------+
# |       dept|      GB|      IN|      US|
# +-----------+--------+--------+--------+
# |Engineering|105000.0| 90000.0|102500.0|
# |         HR|    null| 60000.0| 65000.0|
# |  Marketing|    null| 78000.0| 72000.0|
# +-----------+--------+--------+--------+

# Specify pivot values explicitly (avoids extra scan for distinct values)
df.groupBy("dept").pivot("country", ["IN", "US", "GB"]).avg("salary").show()
```

## Using SQL for groupBy

```python
df.createOrReplaceTempView("employees")

spark.sql("""
    SELECT dept,
           COUNT(*) as emp_count,
           SUM(salary) as total_salary,
           AVG(salary) as avg_salary,
           MAX(salary) as max_salary
    FROM employees
    GROUP BY dept
    HAVING COUNT(*) > 1
    ORDER BY total_salary DESC
""").show()
```

## Common Interview Questions

**Q: What is the difference between count("col") and count("*")?**
`count("col")` counts non-null values in that column. `count("*")` or `count(lit(1))` counts all rows including those with nulls. Use `count("*")` for total row count per group.

**Q: How do you implement HAVING in PySpark?**
Use `.filter()` after `.agg()`. The filter after aggregation is equivalent to SQL's HAVING clause.

**Q: What is the difference between collect_list and collect_set?**
`collect_list` collects all values including duplicates. `collect_set` collects only distinct values (like a set). Both return arrays.

**Q: What does rollup do differently from groupBy?**
`rollup` generates subtotal rows for each level of the grouping hierarchy, plus a grand total row. It's equivalent to `GROUP BY ROLLUP(col1, col2)` in SQL. `cube` generates all possible combinations of subtotals.

## Summary

- `groupBy("col").agg(...)` is the standard pattern for grouped aggregations
- Use `agg()` with multiple functions for multi-column summaries in one pass
- `filter()` before `groupBy` = WHERE; `filter()` after `agg()` = HAVING
- `countDistinct()` counts unique values per group
- `collect_list()` and `collect_set()` aggregate values into arrays
- `rollup` and `cube` generate hierarchical subtotals
- `pivot()` rotates row values into column headers for cross-tab reports
